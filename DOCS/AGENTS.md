# 에이전트 작업 규약 — 음식점 AX 서비스

개발 또는 분석 작업 전에 다음 문서를 읽는다.

1. `음식점_AX_통합기획서_v1.0.md`
2. `음식점_AX_UI명세서_v0.1.md` 또는 사용자가 제공한 최신 UI 명세서
3. 저장소의 `README.md`, 기존 코드, 테스트, 환경 설정 예시

## 필수 원칙

- 1차 목표는 1~2인 운영 음식점의 데이터 입력 부담을 최소화하는 데이터 수집 파이프라인이다. 범용 AI 비서나 POS 대체 제품으로 방향을 바꾸지 않는다.
- POS 수집 모드 A(Toss Open API), B(Toss Plugin SDK), C(CSV/Excel)는 수집 어댑터만 다르고 내부 데이터 모델과 화면은 공통으로 유지한다.
- 연동이 실제로 검증되지 않았다면 실시간 POS 연결, 테이블 데이터, 방문 인원 정보를 제공한다고 표시하지 않는다.
- 판매·원가·재고 계산은 결정론적 코드로 처리한다. LLM이 사실/숫자를 임의 생성하도록 하지 않는다.
- 중복 이벤트, 주문 수정·취소, 시간 기준, 단위 변환, 재고 실사/조정에 대한 테스트를 작성한다.
- POS에 존재하는 값을 다시 수기로 입력하게 만들지 않는다. POS/파일에서 확보되지 않는 정보만 최소 입력으로 보완한다.
- 폐기 카메라 분석, 연령대 카메라 추정, 완전자동 발주는 초기 MVP 범위가 아니다.
- 사용자 결정이 필요한 항목은 통합기획서의 D-01~D-08을 확인한다. 임의로 결정하지 말고 임시 가정은 `PROVISIONAL`로 표시한다.
- 기존 저장소의 기술 스택과 코드 스타일을 먼저 확인하고, 불필요한 재작성이나 광범위한 리팩터링을 하지 않는다.
- 비밀키·토큰·개인정보를 코드, 테스트 fixture, 로그에 넣지 않는다.
