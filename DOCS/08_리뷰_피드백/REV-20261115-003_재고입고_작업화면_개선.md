# 재고·입고 작업 화면 개선 — self-review

구현자가 diff·변경 파일·기존 API/서버 계산 코드를 확인한 자체 검토다. 독립 리뷰나 브라우저 검증이 아니다.

- 상단 카드의 수와 필터는 같은 기존 상태를 사용한다. 부족률은 양수 안전재고 항목에만 계산하므로 단위가 다른 재료를 절대량으로 비교하거나 미설정 분모로 나누지 않는다. 실제 입고 기록으로만 최근 7일 요약을 만든다.
- 카드 클릭·Enter·Space 이후 실제 상태 선택과 표 행이 바뀌는 테스트가 통과했다. 모든 기존 상태 및 전체 필터, 페이지 20행·경계·축소·필터 초기화를 확인했다. 매장 변경은 key로 화면 상태를 재생성한다.
- 고정 높이 식은 기존 메뉴 화면과 동일하다. CSS 원본은 그대로이고 파일 끝에 재고 전용 블록만 붙였다. 표의 세로/가로 스크롤, 헤더·첫 열 고정은 CSS 구현을 확인했으며 실제 화면은 미검증이다.
- 실사 값에서 날짜를 분리했고, 버튼/빈 슬롯 폭을 맞췄다. Tooltip의 터치 tap·포커스 always와 날짜가 포함된 접근성 이름을 확인했다. 실제 기기 터치와 스크린리더는 미검증이다.
- 폐기·보정 사유 선택 뒤 부호 방향과 수량 입력이 배치된다. 폐기 두 사유는 음수 고정, 보정·기타는 양방향. 사유 변경·입력 오류·API payload·실패 후 입력 보존을 테스트했다. 서버 계약을 바꾸지 않았다.
- 빠른 기록 3개는 기존 모달/저장 경로를 연다. 입고의 구매 단위·금액과 실사의 0 허용을 테스트했다. 기존 행별 기록 버튼과 식자재 관리 이동도 유지했다.
- 이력 표는 기존 열을 보존하고 50건 제한을 제거했다. 메뉴는 기존 메뉴·레시피 조회로 연결하며 로딩/실패/미선택/빈 레시피가 전체 목록으로 바뀌지 않는다. 현재 레시피 기준이라는 한계를 IR에 기록했다.
- 실사 기본 단위·서버 저장·기준 시점·재고 식·소모 조건을 조사했다. 구매 단위/남음 단계/핵심 재료 확인 대안은 IR에 의견으로만 적었고 로직·데이터는 바꾸지 않았다.
- 백엔드·API·DB·IngredientManagementPage·의존성·금지 경로 변경이 없다. U 번호를 새로 쓰지 않았다. 개발 서버·push·merge·배포를 실행하지 않았다.

자동 검사: tsc -b·ESLint 경고 0·Vitest 기존 포함 77개·Vite build 통과. 디자인 lint 0 FAIL, 실제 모달 그림자/결측 표시 경고 2건은 유지 사유가 있다. 검사 상세와 번들 경고는 IR에 기록했다.

검토 중 수정: 최근 7일 기준 시각이 화면 진입 시각에 고정되면 새 입고가 요약에서 빠질 수 있어, 조회 완료 시각으로 갱신하도록 변경하고 재조회 회귀 테스트를 추가했다. 페이지/필터 변경 시 스크롤 영역도 새로 시작하도록 했다.

구현·자동 검사 범위에서 PASS. 실기기·브라우저(배율·전체 스크롤·터치·툴팁·모달 포커스), 실제 API는 후속 확인이 필요하다. 실사 정책은 임의 확정하지 않았다.
