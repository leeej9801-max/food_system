# 메뉴 관리 표 밀도 개선 — self-review

독립 리뷰가 아닌 구현자의 자체 검토다. 변경 diff·전체 파일·자동 검사로 확인했다.

- 요약 카드의 전체 필터, 유형 줄 안의 추가·취소·입력, 기존 검색·상태·행 작업·모달 콜백을 확인했다.
- 필터 변경 시 페이지 초기화, 목록 축소 시 보정, 전체 기준 행 번호를 확인했다. 빈 목록에서도 표 공간과 페이지 하단이 유지된다.
- 높이 계산에서 App 래퍼의 위·아래 여백 총 3rem을 제외한다. CSS는 메뉴 화면에 한정한다. 다른 화면의 body zoom·레이아웃은 건드리지 않았다.
- 운영 전환은 행별 임시 값으로 문구도 즉시 바뀐다. 저장·재조회 성공 전에는 완료 알림이 나오지 않으며, 실패 시 예외가 Switch에 전달되고 임시 값이 정리된다. 회귀 테스트가 두 경로를 검증한다.
- 레시피 상태 세 종류의 색상·버튼 요소·메뉴명 포함 접근성 이름을 확인했다. 별도 보기 버튼은 없다.
- API·백엔드·홀 화면·금지된 의존성 파일 변경 없음. 실제 데이터·자격증명 추가 없음. 기존 LF 유지.

발견 후 수정: 손잡이만 먼저 바뀌고 문구가 서버 응답까지 남지 않도록 행별 임시 값을 추가했다. 저장 성공 후 재조회까지 기다리도록 해 확정 전 깜박임을 줄였다.

구현·자동 검사 범위의 결과는 PASS다. 추가 확인 권장: 실기기·브라우저에서 높이·스크롤·터치·모달·실제 애니메이션(미검증). 정적 검사나 서버 렌더링 테스트로 이 확인을 대신했다고 주장하지 않는다. 최종 타입·린트·46개 테스트·빌드가 통과했다. 커밋 훅은 커밋 시 실행한다.
