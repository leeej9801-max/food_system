## 2. 체크리스트 점검

| 점검 항목 | 결과 | 근거 |
| --- | --- | --- |
| 기획 의도(1~2인 음식점 데이터 수집·정규화·원가·재고 파이프라인) 준수 | PASS | 범용 AI 챗봇이나 POS 대체 기능 없이 S00~S07 데이터 파이프라인에 집중 |
| 미검증 POS 연동 과장 금지 (`UNVERIFIED` / `PROVISIONAL`) | PASS | 모드 A/B는 `UNVERIFIED`, 모드 C는 `READY_CSV`(`is_realtime: false`), 미연결 메뉴는 `UNLINKED_PROVISIONAL` 명시 |
| 가짜 판매 데이터 주입 금지 | PASS | 기본 점포 및 양식 비스트로 데모 시드 모두 가짜 판매 데이터 0건 보장 |
| 결정론적 `Decimal` 계산 및 반올림 일관성 | PASS | 단위 변환, 원가율(`ROUND_HALF_UP`), 이론 소모량, 예상 재고 모두 `Decimal` 연산 |
| 데이터 입력 순서 독립성 (CSV 선업로드 ↔ 메뉴 후등록) | PASS | 메뉴 생성/수정 시 `_retroactive_link_unmapped_sales`가 미매칭 판매 항목을 자동 소급 연결 |
| 실재고 실사 이후 과거 영업일 CSV 업로드 시 재고 차감 오염 방지 | PASS | `item_ord_dt.date() < baseline_dt.date()` 가드로 과거 매출 중복 차감 차단 |
| 백엔드 N+1 쿼리 제거 및 프론트엔드 빌드 무결성 | PASS | `imports.py`, `ingredients.py`, `inventory.py` 배치 조회 및 `O(N)` 인덱싱 완료 |

## 3. 잔여 리스크 및 향후 권고 사항

- 현재 모든 P0 요구사항(`REQ-001`~`REQ-012`)과 화면(`S00`~`S07`)이 연결된 엔드투엔드 파이프라인으로 동작하며, 향후 실제 토스플레이스 Open API / Plugin SDK 자격증명 확보 시 모드 A/B 어댑터만 교체하면 내부 정규화·원가·재고·집계 파이프라인은 코드 변경 없이 그대로 재사용 가능하다.
