# 음식점 서비스 서브도메인 분리 — self-review

구현자가 최종 diff·빌드 결과·격리 nginx와 Cloudflare 실제 설정을 확인한 자체 리뷰다. 독립 리뷰·운영 재배포 검증이 아니다. 구현 및 사전 검사 범위에서 PASS이며 운영 전환은 사용자 지시 전까지 보류한다.

- Docker base·dist 복사 위치·라우터 BASE_URL·API prefix·nginx upstream URI·CORS·healthcheck가 루트 배포 기준으로 일치한다. 기존 로컬 API 주소와 동기 3계층·데이터 모델을 보존했다.
- `$request_uri` map은 정확한 구 호스트와 `/food` 경계에만 적용된다. 쿼리·인코딩 보존, `/foodish` 제외, 새 호스트 리다이렉트 미적용을 실제 임시 nginx 요청으로 확인했다. API strip은 제거됐다.
- 첫 nginx 검사 실패는 기존 외부 폰트 CSS의 오분류였다. 외부 URL을 제외하고 로컬 자산의 `/assets/` 시작 조건은 유지해 수정 후 통과했다. API 인코딩 URI 검사도 포함한다.
- tsc·Vitest 7파일 85개·ESLint 경고 0·Vite build, nginx -t 및 HTTP 검사, Compose 문법 검사가 통과했다. zod·큰 청크 경고와 초기 실패를 IR에 기록했다.
- Cloudflare 현재 version 4가 이전 after 백업과 같음을 확인했다. before의 lci 두 규칙·마지막 404·warp-routing을 그대로 보존한 추가였으며 이번에는 PUT하지 않았다. DNS API 403 후 ego-browser로 `food` 부재를 확인하고 지정 CNAME만 Proxied로 추가했다.
- DNS 저장 후 목록 행·공용 DNS·HTTPS 도달을 확인했다. 새 루트 404와 구 `/food/` 200은 전환 전 운영 상태로 정확하게 기록했다. 운영 정상화·301 전환을 완료로 표시하지 않았다.
- 본 저장소 변경·커밋·push·병합·운영 restart/up·운영 DB 변경·카카오 콘솔 변경을 하지 않았다. 비밀은 출력·새 파일·문서에 남기지 않았다. 전용 임시 컨테이너·네트워크와 브라우저 작업 공간을 정리했다.
- 과거 DOCS 기록을 고치지 않고 현행 허브·인수인계·변경이력과 이번 WO·IR·REV에만 상태를 추가한다.
- 문서 링크 검사는 111파일·954링크, 중복 0·기존 깨진 링크 1건이다. 해당 오류의 HEAD 존재와 대상 문서 부재를 확인했고 신규 링크 오류는 없다. 최종 diff 공백 검사도 통과했다.
