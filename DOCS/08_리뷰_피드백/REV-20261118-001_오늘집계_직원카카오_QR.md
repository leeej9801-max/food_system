# 오늘 집계 · 카카오 · QR — self-review

구현자의 자체 검토이며 독립 보안 리뷰/실계정 로그인 성공/운영 출시 승인으로 해석하지 않는다. 결과는 **PASS_WITH_ACTIONS**다.

## 검토 및 수정

- endpoint → 동기 서비스 → repository를 유지했다. 오늘 집계는 응답 schema를 분리하고 기존 완료 매출 함수를 재사용한다. Seoul 자정 직전/정각/다음 자정, 뉴욕 DST 25시간 일자와 다른 매장 격리를 검사했다.
- 새 직원 쿠키/세션은 기존 점주·손님과 분리한다. state와 PKCE, 정확한 Origin, JWT 알고리즘/issuer/audience/만료, 1회용 초대 해시, refresh 해시·절대 만료·회전·재사용 폐기를 검토했다.
- DB의 세션 폐기를 매 요청에 반영하므로 access 유효기간이 남아 있어도 재사용/퇴사 폐기가 즉시 듣는다. PENDING 직원의 로그인은 허용하되 QR 기록은 거부한다.
- 직원 행 잠금 이후 종류를 결정하고 이벤트+QR 사용을 같은 트랜잭션으로 남긴다. 기존 owner-direct 60초 병합을 QR에 적용하면 빠른 IN→OUT→IN이 과거 IN으로 합쳐지는 문제를 발견해 QR에만 제외했다. UUID 멱등성과 기존 수동 API 기본 동작은 유지한다.
- SQLite 시간대 제거로 재시도 JSON이 달라지는 문제를 응답 UTC 정규화로 고쳤다. 비ASCII QR 입력은 형식 검증으로 차단해 비교 함수의 TypeError를 방지했다.
- OAuth code/state·카카오 토큰·쿠키·원시 QR을 제품 로그/문서에 넣지 않는다. 민감 경로는 예상치 못한 예외의 Starlette 재전파도 차단해 uvicorn traceback으로 새지 않게 하고 회귀 검사했다. callback query도 가린다. 별도 배포 프록시/플랫폼의 접근 로그 설정은 사용자 수동 점검이 필요하다.
- 모바일 재스캔이 같은 라우트의 초기 state를 재사용하는 문제를 route key로 해결했다. 실제 브라우저에서 새 fragment 제거와 재기록을 확인했다. 모달 QR/카운트다운·폴링 완료, 직원 승인·초대 생성, 390px 독립 화면을 확인했다.
- Antigravity의 보호 파일 중 AttendancePage만 마지막 최소 연결 diff를 적용했다. attendance.css와 lib/attendance.ts를 수정하거나 되돌리지 않았다. 프론트 manifest/lock도 변경하지 않았다.
- 새 마이그레이션은 0016 하나이며 0014/0015는 보존했다. downgrade가 원본/정정을 보존하되 새 인증 메타데이터는 제거한다는 범위를 IR에 명시했다.

## 검증

근태 전체 pytest 최종 **50 passed**(SQLite 49/독립 PostgreSQL 1). 앞선 보강 focused **5 passed** 뒤 민감 예외 전파 검사와 callback 303 계약을 더해 전체 재실행했다. backend 전체 ruff·pyright 통과, frontend tsc·변경 ESLint 통과, Vitest **100 passed**, Vite build 통과. OpenAPI snapshot 일치와 요청 PNG 4개를 확인했다. 상세 결과·경고·초기 실패는 IR에 보존했다.
