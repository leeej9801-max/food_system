## 검토 내용

- 엔드포인트 → 동기 서비스 → repository 경계를 유지했다. SELECT/INSERT는 repository에서, 검증·감사 기록·commit은 서비스에서 수행한다.
- 원본 키 중복/60초 중복은 직원 행 잠금 이후 처리한다. 정확한 키 조회는 순서 검증보다 먼저 하여 이후 OUT이 있거나 비활성화된 경우에도 기존 응답이 유지된다. 60초 중복에 사용한 별도 UUID도 추가 전용 연결 표에서 조회한다.
- 신규 출퇴근만 비활성 상태를 거부한다. 직원 DELETE는 상태만 바꾸고 원본·정정·스케줄 FK 및 과거 이력을 보존한다. 기본 목록 ACTIVE와 include_inactive 옵션을 구분했다.
- 감사 기록은 응답 스키마로 필드를 제한하며 업무 변경과 같은 트랜잭션이다. 잘못된 정정·스케줄 충돌은 감사 기록을 남기지 않는다. 기존 RequestContext actor를 유지한다. 실제 신원은 인증 후속 작업이 필요하다.
- 원본/정정의 기존 트리거를 그대로 사용한다. 새 감사·재요청 키 표도 PostgreSQL 트리거와 런타임 권한으로 보호한다. 역할 설정 재실행 시 권한이 복원되지 않도록 했다.
- 0015만 추가하고 0014는 수정하지 않았다. 기존 이벤트 UUID backfill 외의 원본 변경은 없다. downgrade에서 새 메타데이터가 제거되는 범위를 IR에 기록했다.
- 프론트 변경은 API 클라이언트의 기본 UUID 생성·전송 및 같은 키 재시도 인자뿐이다. 화면·CSS·공통 헤더는 수정하지 않았다. 기존 미커밋 작업을 stage/commit/reset하지 않았다.
