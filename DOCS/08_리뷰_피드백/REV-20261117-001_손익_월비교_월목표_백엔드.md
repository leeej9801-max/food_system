# 손익 월 비교·월 목표 백엔드 — self-review

구현자가 코드·diff·생성 계약·실제 테스트 결과를 검토했다. 독립 리뷰는 아니다.

- 비교 응답의 필드명과 nullable 조건이 사용자 계약과 일치한다. 지난달 전체는 trend[-2]를 그대로 사용한다. 누계는 `_daily`를 재사용하며 날짜 없는 수기 월 매출·비용을 넣지 않는다. 현재 월·과거 월·미래 월, 윤년 2월·평년 2월·연말·UTC/서울 월 경계의 API 테스트가 통과했다.
- 목표는 nullable bigint이며 매장·월 고유 제약과 PostgreSQL 원자적 upsert를 사용한다. 100억·-100억·0·일부 생략·null 초기화, 동일 행 갱신, 감사 기록과 PUT/GET 전체 응답 일치를 검증했다. 잘못된 범위·타입·월은 422, 없는 매장은 404다.
- 새 테이블은 월 비용과 같은 RLS ENABLE/FORCE 및 USING/WITH CHECK 정책을 갖는다. 런타임 계정에서 무범위 SELECT는 0행, 다른 매장 UPDATE/DELETE는 0행, INSERT는 RLS 오류로 차단된다. 정상 매장별 PUT/GET도 통과했다.
- 생성 OpenAPI는 새 스키마·필드·경로만 추가한다. 프론트 표본은 실제 테스트 API 호출로 재생성했고 손익 시각을 고정했다. 프론트 구현·의존성·환경 파일은 수정하지 않았다.
- 검증: 집중 34개, API 115개, 전체 143개 통과. 전체 경고 3개는 기존 deprecation이다. Ruff check·95개 파일 format check·Pyright 오류/경고 0, 개발 DB 0014 적용 및 구조 확인 완료.
- 기존 문서 링크 오류 1건은 이번 변경과 무관하며 IR에 위치를 기록했다. 신규 링크 오류는 없다.

구현·자동 검사 범위에서 PASS. 프론트·브라우저·실기기, 운영 DB 적용, POS 실연동, migration downgrade와 동시 요청 부하 검증은 수행하지 않았다. commit·push·추가 위임 없음.
