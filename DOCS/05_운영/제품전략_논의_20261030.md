# 제품 전략 논의 기록 (2026-10-30)

> 상태: **논의 기록 (미확정)**. 여기 적힌 방향은 아직 사용자 결정이 아니며, 확정되면 [[결정사항_로그]]에 U-xx로 기록하고 작업지시서(WO)로 만든다.
> 경쟁사 정보는 각 업체 홈페이지 문구만 확인한 것이며 실제 앱 동작은 검증하지 않았다 (`미검증`).

## 1. 논의 배경

- 사용자는 제품 상용화를 목표로 한다. 우려: 대시보드는 누구나 만들 수 있어 경쟁력이 낮고, AI가 없으며, POS·키오스크·테이블오더 경쟁사가 많다.
- 사용자는 이미 "2D 도트 매장 현황"(S02 홀)을 만들었다. 원래 의도는 직원용이 아니라 **큰 TV(매장 내부/외부)에 마케팅 + 매장 현황을 보여주는 것**이다.
- 요청: 도트 고도화와 별개로, **다른 분야에서 가져온 독보적 아이디어**가 필요하다.

## 2. 경쟁사 조사 (홈페이지 기준)

| 업체 | 본업 | 재고·원가 | AI |
|---|---|---|---|
| 토스플레이스 | 무료 POS, 키오스크, QR오더, 배달앱 연동 | 소매 중심 재고(바코드) | 언급 없음 |
| 페이히어 | 테이블오더 태블릿, 수수료 0원 | 메뉴 링크만 있음 | 언급 없음 |
| 셀버스 | 키오스크, 사이니지, 스탬프, 프랜차이즈 | 언급 없음 | "AI에이전트" 메뉴명만 있음, 내용 없음 |
| **주담(judam.kr)** | 레시피 기준 식자재 자동 차감, 발주, 유통기한, 일일 리포트 | **핵심 기능** | 언급 없음 |

- 주담이 우리와 가장 크게 겹친다: POS 중립(오케이포스·이지포스·포스뱅크·나이스·토스·네이버), 수수료·세금 반영 순이익, 월 9,900원(연 결제 7,900원), 7일 무료 체험, 30분 방문 세팅.
- 결론: "재고·원가 대시보드"만으로는 차별화가 안 된다.
- 주담 POS 연동 방식은 공개 자료로 확인되지 않았다. `JudamBridge_Setup_1.0.2.0.exe`(약 4.0MB, 2026-01-05 수정)가 매장 PC 상주 에이전트로 보이나 **추정**이다.

## 3. 검토한 아이디어와 판정

### 폐기 (사유 포함)

| 아이디어 | 폐기 사유 |
|---|---|
| OCR 거래명세서 | 인식률 99% 필요, 작은 기능이라 차별점이 못 됨 (부가 기능으로는 가능, 확인 후 수정 흐름 전제) |
| 재고 기반 "마지막 N그릇" / 폐기 임박 자동 서비스 / 빈자리·대기시간 TV | 특정 가게 한 케이스에 맞춘 나노 기능이라 제품화 시 안 쓰임. 빈자리는 `미검증` 데이터 |
| 식자재 시세판 + 메뉴 포트폴리오 (증권 앱) | 표본 가게 수, "동네" 정의, 이커머스 식자재 포함 여부 등 가정이 많아 정확도 낮음 |
| 익명 동종업계 벤치마크 | 원가는 민감 정보라 초기 공유 불가, 원가율 높은 사장에게만 유용 |
| 가게 시뮬레이터 | 원가 시나리오와 사실상 동일, 코드 기반이라 AI 요소 없음 |
| 금융 리포트 | 현실성 없음 |
| 듀오링고식 게이미피케이션 | 생업 도구와 학습 도구는 결이 안 맞음 |
| 주방 음성 운영 비서 | 얻는 것 대비 리스크가 큼 (주방 소음, 외부 채널 쓰기 연동 미검증) |
| 레시피 기반 AI 전화 응대 | 직원이 내용을 다시 확인해야 해서 부담 |
| 주방 부하 기반 대기시간 | 화구 수 변화, 주문 취소, 재조리 등 변수가 많고 실시간 입력이 사실상 불가능 |

### 유효 (계속 논의)

- **날씨 연동 도트 테마**: 기상청 API로 날씨·시즌별 분위기/테마를 바꾼다. 업데이트로 해결 가능하다는 판단.
- **손님용 도트 캐릭터 + 메뉴 도감**: 첫 방문 손님이 자기 도트 캐릭터를 만들고, TV의 도트 레스토랑에 입장·착석하는 모습을 본다. 재방문하면 같은 캐릭터가 입장해 소소한 단골 챙김과 친밀감을 준다. 사용자 평가: "아이디어는 좋다". 주문 기록은 POS가 정확히 갖고 있고 직원 확인이 필요 없다는 점이 강점.
- **판매 데이터 기반 홍보 콘텐츠 자동 생성**: 단독 판매는 약하고(캔바·일반 AI와 겹침) 도트 TV/도감에 붙는 부가 기능으로 적합.

### 아이디어 선별 기준 (사용자 피드백에서 도출)

1. 사람이 실시간으로 입력해야 하면 탈락
2. 직원이 다시 확인해야 하면 탈락
3. 변수가 많아 정확도가 흔들리면 탈락
4. 특정 가게 한 케이스만 다루는 기능은 제품 기능이 못 됨
5. 내부 운영과 고객 편의 중 **한 쪽만 만족해도 가능**
6. 가게 1곳만으로 동작하고, 가게 간 데이터 공유에 기대지 않을 것

## 4. 손님 캐릭터 흐름 설계안 (제안, 미확정)

**원칙:** 꾸미기와 저장을 모두 선택 사항으로 둔다. 40대 이상도 설명 없이 쓸 수 있어야 한다.

- 첫 방문: 테이블 QR을 폰 기본 카메라로 찍음 → 랜덤 캐릭터 즉시 생성(앱 설치·가입 없음) → TV에서 입장·착석 → 폰에는 **[다시 뽑기] / [이대로 좋아요]** 두 버튼 → 선택적으로 **[카카오로 저장]**.
- 재방문: QR을 찍으면 저장된 손님으로 인식, 방문 횟수에 따라 장식(모자, 단골 배지) 자동 부여.
- 저장 방식: 카카오 1탭(권장, 앱 검수 필요) > 브라우저 쿠키(비저장 손님용 임시) > 전화번호(동의 절차 무거워 후순위).
- 공개 TV에는 이름·닉네임을 띄우지 않고 캐릭터만 보여준다.
- 이미 토스/페이히어 QR이 테이블에 있는 가게는 QR이 2개가 되는 혼란이 있다. 대안: TV 구석 QR → 테이블 번호 선택(탭 1회 추가).
- 체크인한 손님의 연출이며 실제 착석 현황이 아니다. 따라서 D-02/D-03 자리·인원 `미검증` 상태와 충돌하지 않는다.

## 5. 미해결 질문 / 위험

- QR 스캔율이 실제로 얼마인지 (매장 1곳 파일럿으로 측정 필요).
- 손님 식별 방식(카카오 로그인 사업자 검수, 개인정보 동의 수준).
- CSV 모드(C)에는 손님별 주문 정보가 없을 가능성 (미확인).
- 도트 컨셉 자체가 시장에서 먹히는지 (검증 전). 도트 TV·도감·콘텐츠가 한 세계로 묶여 있어 컨셉이 안 먹히면 함께 약해진다.
- 다른 분야에서 가져오는 아이디어는 사용자가 **별도로 계속 시도하기로 함**. 이번 후보는 대부분 폐기됨.

## 6. 경쟁사 POS 연동 조사

- 주담 연동 방식은 비공개. 한국 POS 연동 일반 패턴(추정): ① POS 로컬 DB 읽기, ② 영수증/주방 프린터 출력 파싱, ③ POS사 제휴 API/SDK.
- 역분석(REA 등)은 권하지 않기로 함. 저작권법 제101조의4는 호환 목적 외의 역분석과, 얻은 정보를 유사 프로그램 개발에 쓰는 것을 허용하지 않는다. 이용약관 위반 소지도 있다 (약관 미확인). 법률 자문이 아니며, 진행 전 전문가 확인이 필요하다.
- REA(`github.com/morluto/rea`, npm `rea-agents`)는 MCP 서버 형태의 정적 분석 도구로, 분석 자체는 로컬에서 돌지만 결과가 연결된 AI 에이전트 제공사로 전송된다. 주담 서버에는 정적 분석 기록이 남지 않으나, 다운로드 로그는 남았을 수 있다.
- 합법적 대안: (a) 가상머신에 설치해 파일·포트·통신 주소만 관찰하는 블랙박스 관찰, (b) **POS사(오케이포스, 이지포스, 포스뱅크, 토스플레이스 등)에 제휴·연동 API 직접 문의**. (b)가 모드 A/B의 `미검증`을 실제로 해소하는 가장 확실한 길이다.
