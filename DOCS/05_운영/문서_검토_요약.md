## 2. 문서별 역할과 핵심 지침

### 2.1 통합기획서 v1.0 — 제품 기준 (최상위)
- **문제/목표:** 1~2인 매장이 별도 데이터 담당자 없이 운영 데이터를 축적. 중복 수기 입력 제거, POS·CSV를 공통 형식으로, 메뉴·레시피·식자재 연결, 실측/추정/원본 구분.
- **비목표:** POS 대체, ERP, 무승인 자동 발주/가격 변경, 카메라 필수, 근거 없는 예측.
- **MVP P0(13개):** 매장 생성, 테이블 배치, 수집 방식 A/B/C 설정, CSV/Excel 판매 업로드, 메뉴 마스터, 식자재 마스터, 레시피, 입고·구매가격 이력, 실재고·예상 재고, 메뉴/시간대 판매 집계, 수집 상태 표시, 원가·가격 시나리오, 수정 이력·중복 방지 → [[요구사항_ID_매핑]]에서 `REQ-001~013`으로 부여.
- **P1:** Toss Open API/Plugin 실연결, 발주 검토 알림, 대시보드 고도화, 오프라인 등. **P2(보류):** 카메라 분석, ML 수요예측, 자동 발주, 다중 매장.
- **데이터 개념:** 마스터(매장·테이블·메뉴·POS 매핑·식자재·공급업체·레시피) / 이벤트(주문·결제·테이블 세션·입고·실사·조정) / 파생(집계·이론 소비·예상 재고·원가). 출처 메타데이터(`source_type`, `source_record_id`, `source_event_time`, `received_at`, `import_batch_id`, `quality_status`).
- **계산 규칙:** 시간 기준(항목 시각 > 주문 시각, 결제 시각≠주문 시각), 취소/수정 반영, 중복 방지, 이론 소비량, 예상 재고식, 원가·식재료비 비율.
- **미결정:** D-01 POS, D-02 방문 시작 시점, D-03 인원/연령 기록, D-04 시간 기준 필드, D-05 원가 단가, D-06 실사 빈도, D-07 오프라인, D-08 업종.

### 2.2 기술아키텍처 v1.0 — 기술 기준
- **스택(선정):** React+TS+Vite, React Router, TanStack Query, Tailwind+shadcn/ui(권장), FastAPI, Pydantic v2, SQLAlchemy 2.x, Alembic, PostgreSQL 18(미지원 시 17), pytest. Redis/Kafka/K8s 제외. REST polling.
- **구조:** 모듈형 모놀리스 + 같은 코드베이스 worker. `frontend/`, `backend/app/{api/v1/endpoints,db/models,schemas,services,integrations,worker}`, `backend/tests/{unit,api,integration,fixtures}`.
- **API:** `/api/v1/...`, 필드별 오류, 미연결/권한/지연/미존재 구분, 업로드는 preview→commit.
- **DB 원칙:** store_id 범위, numeric 금액/수량, UTC 저장, 외부 ID 매핑, CASCADE 지양, 단계적 migration.
- **ADR-001~012**(ADR-011 클라우드·인증, ADR-012 원가 기준 미결정).
- **미결정 표 §14:** `D-01~D-11` — **통합기획서 D 번호와 의미가 다름**(충돌 C-02).

### 2.3 UI 명세서 v0.1 — 화면 기준(초안)
- 화면 S00~S07(P0: S00~S05, P1: S06~S07). 공통 상태(연결/최신성/매핑/레시피).

- 미확정 8개(방문 기록 시점, HOME 우선 정보, 연령대, POS, CSV 형식, 폐기 범위, 실사 범위, 보관/백업).

### 2.4 개업전후 로드맵 — 사업 맥락(참고)
- 개업 전: 메뉴·레시피·원가·구매 데이터 구축이 핵심, 개업 후 30/60/90일 단계 확장.
