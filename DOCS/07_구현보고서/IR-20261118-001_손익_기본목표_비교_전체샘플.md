# 손익 기본 목표·기간 비교·전체 샘플

> **현재 상태 주의(2026-11-18):** 아래 기본 목표·0015 및 목표 PNG는 이 작업이 구현·확인한 당시 상태다. 대기 중 공유 폴더에서 기본 목표 필드/0015가 제거되고 `inherited_from`을 쓰는 최근 월 목표 이월 방식으로 바뀐 것을 확인했다. 다른 변경을 되돌리지 않았으며 C-10으로 기록하고 사용자에게 기준을 질문했다. 현재 목표 계약의 완료·승인을 뜻하지 않는다. 비교/seed 독립 검사는 별도 이름의 일회용 DB·역할로 진행한다.

## 구현
- 기존 `design/pnl-ux` 미커밋 변경을 보존하고 구현했다. commit/push/stage 없음. 패키지/lock/skill/agent/환경 파일과 DOCS 이미지·zip은 수정하지 않았다.
- `Store.default_revenue_target/default_profit_target`: nullable bigint. 기존 PUT `/stores/{id}/pnl/{month}/goal`에 `scope: default|month`(생략 시 month). 두 목표는 전체 대체, 월 필드 null은 각 기본값 fallback, 월 0은 명시적 값이다. 응답 goal에 적용값, 원본 default/month 값, `revenue_source/profit_source`를 반환한다. 기본 목표도 감사 로그를 남긴다.
- 목표 모달의 기본/이번달만 선택·해제, 카드의 기본/이번달 표시 및 이익 목표, 저장 후 해당 매장 전체 손익 캐시 무효화. 기존 KPI 색·그리드·차트·반원 게이지를 보존했다.
- 비교 선택은 기존 전월 동기와 새 3가지 기준을 하나의 KPI 위 비교 영역에 배치했다. 월 KPI 주 숫자는 월 손익을 유지하고 비교 영역에 선택 기간의 매출·지출·이익 및 기준 금액을 명시한다. 증감은 기존 kpiDelta(기준 0/작음/부호 전환은 금액, 자료 없음은 미산출)를 사용한다. Astryx Tooltip은 터치 탭·키보드 포커스를 지원한다.

## 계산 정의 (PROVISIONAL, WO 가정)
- 매장 timezone의 오늘 기준. 과거 조회월은 말일, 미래월의 새 비교는 미산출.
- 주단위: 월요일~기준일 vs 7일 전 같은 요일 범위. 월 경계 포함.
- 월평균: 선택 월 손익 vs 직전 N개 완료월 평균. API `average_months` 1~6, 기본 3. 현재 월은 기존 손익표와 동일하게 입력된 월 수기 비용 전체를 포함한다.
- 주평균: 이번 주 진행분 vs 직전 4개 완료주(월~일) 평균. 기간 차이는 툴팁과 비교 영역에 명시한다.
- 새 주 비교는 실제 일별 판매·입고를 쓰고 수기 월 매출·비용은 그 월 달력 일수로 안분한다. 자동 카드수수료는 해당 매출 기준. Decimal 계산 후 원 단위 반올림, 이익=반올림 매출-반올림 비용. 평균도 매출/지출 평균을 반올림하고 이익은 차감한다.
- 기록 없는 기준 구간을 0으로 만들지 않는다. 평균 구성 구간 중 기록 없는 월/주가 있으면 평균은 null. 명시적 0원 기록은 자료로 인정한다. 기존 전월 동기와 달력은 날짜 없는 월 수기 비용 제외 기준을 유지한다.

## 전체 샘플
- 설정의 기존 `seed-western-demo` 버튼/서비스를 확장했다. 매장 timezone 오늘 기준 6개 완료월+이번 달 오늘까지. 2026-11-18이면 2026-05-01~11-18이다.
- 고정 `Random(20261118)`, 평일/금~일 주문 수 차이, 점심/저녁 시간대, 영업요일 휴무 반영(미설정 시 월 휴무 가정). 양식 4메뉴·5식자재·레시피, 주문/품목, 방문/인원 슬롯, 일별 입고/단가, 월말 실재고, 월 고정비를 공통 데이터로 생성한다. 실제 테이블을 재사용하고 없으면 샘플 4개 생성. 방문은 전부 퇴점 기록이다.
- 식자재 사입 합계는 일 매출의 32%를 식자재 사용량 비중으로 배분. 완료 6개월 평균 매출로 임대료/직원인건비/보험/공과금 등 월 고정액을 고정하고 현재 월은 경과 달력 일수만큼 기록한다. 기존 카드수수료율 가정은 유지한다. 실매장 값이나 실 POS 데이터가 아니다.
- 샘플 식별자 `demo:bistro:v2`(주문 source_mode, 방문 source, 재고 notes, 월 비용 label)인 기록만 교체한다. 이전 초기 샘플 입고는 정확한 notes+공급처 조합으로 교체한다. 사용자 수기 비용 코드가 있으면 그 코드는 보존하고 샘플로 겹쳐 만들지 않는다. 사용자 주문/입고/재고/방문은 삭제하지 않는다. 기존 마스터와 기존 seed의 레시피 upsert 경로를 재사용한다.
- 자료 입력·개인정보·인증키 없음. POS A/B 실연동·실시간 지원을 주장하지 않는다. 설정 성공 안내와 버튼에 샘플 범위를 표시하고 전체 화면 캐시를 갱신한다.

## 미확인
운영 DB·downgrade·실기기·실 POS·동시 부하 검증은 범위 밖이다. 새 주 비교와 기존 전월 동기는 수기 비용 처리 기준이 다르며 툴팁에 설명했다. 샘플에 사용자 데이터가 섞여 있거나 메뉴 가격·수수료 설정이 달라지면 보존한 실제 값에 따라 시연용 10~20% 이익률 범위를 벗어날 수 있다.
