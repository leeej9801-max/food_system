## 1. 구현한 요구사항 / 화면 / 결정 ID
- **도면 배치 (U-31):**
  - 좌표계를 24×28칸(1칸 ≈ 34cm)으로 넓혔다.
  - 테이블 방향 `H`(가로)와 `V`(세로)를 추가했다.
  - 매장 도면 고정물(입구·카운터·주방·칸막이·창)을 추가했다.
  - 매장 A(meal love) 프리셋을 만들었다. 12테이블(가로 8·세로 4), 4인석, 도면을 바른 방향으로 놓은 배치다.
- **사람별 성별·연령대 (U-31, 성별 신규):**
  - 손님은 자기 자리에만 입력한다.
  - 직원은 손님이 비워 둔 자리만 입력한다. 손님 값이 우선이다.
  - 세션 대표 연령대는 사람별 값에서 다시 계산한다.
- **방문 목적·동반 관계:** 세션 단위로 입력한다. 손님과 직원 모두 넣을 수 있고, 손님 값이 우선이다. 선택지는 PROVISIONAL이다.
- **자동 닫기 `END_OF_DAY` (U-19, U-31):**
  - 지난 영업일의 열린 세션을 닫는다.
  - 퇴점 시각은 영업 종료 시각으로 기록한다.
  - 별도 스케줄러는 쓰지 않는다. 홀·방문·손님 API를 호출할 때 먼저 정리한다(지연 닫기).
- **공휴일 (U-28):**
  - 전역 `holidays` 테이블을 만들었다.
  - 천문연 특일정보 수집 스크립트를 만들었다.
  - 조회·수동 추가 API와 `day_type`(평일/주말/공휴일)을 만들었다.
- **기록 화면 S02:** 도면과 입력 패널을 한 화면에 둔다. 태블릿 가로는 좌우, 세로는 위아래 배치다. 문서 스크롤이 없다.

## 5. 미구현 / WO와 다르게 한 것
- **배치 편집 위치 변경:**
  - WO §2.7은 설정 화면에서 편집하기로 했다. 실제로는 HOME 도면의 "배치 편집"(테이블 선택 → 빈 칸 탭, 방향 바꾸기)으로 구현했다.
  - 이유: 도면이 HOME에 있어 같은 화면에서 옮기는 편이 쉽다. 설정 화면을 다시 만들 범위도 줄었다.
  - 설정 화면은 좌표 숫자만 보여 준다. 설정에서 새로 만든 테이블은 예전 위치값으로 생긴다. HOME에서 옮겨야 한다.
- **설정 화면 좌표 편집:** 하지 않았다(후속).
- **도면 고정물 편집 UI·API:** 없다. 프리셋 스크립트로만 넣는다. `StoreUpdate`에 넣지 않았다.
- **기존 `PixelFloorMap.tsx`:** 더 이상 쓰지 않지만 지우지 않았다. "2D 도트 홀" 켜기는 이제 도면 색만 바꾼다.
- **연령 메모 방식 제거:** 예전 HOME의 연령별 인원 메모(`notes`에 적던 방식)는 사람별 입력으로 대체했다. 예전 세션의 메모 문자열은 그대로 남는다.
- **인원 8명 이상:** 인원 버튼은 1~8이다. "8+"를 눌러도 8명이다. 9명 이상은 손님 `+` 또는 직원 API로만 늘린다.
- **천문연 실제 호출:** 하지 않았다. 인증키가 필요하다.

## 6. POS / 외부 연동 상태
- POS 변경 없음(`UNVERIFIED` 유지).
- 천문연 특일정보 API는 응답 형식 테스트만 했다(`미검증`). 실제 엔드포인트와 응답은 공공데이터포털 문서 기준이며, 인증키를 넣은 뒤 첫 수집 때 확인해야 한다.

## 7. 기술 부채 / 위험
- **지연 닫기:** 아무도 API를 호출하지 않으면 DB에는 열린 채로 남는다. 후속 분석 쿼리도 먼저 정리를 호출해야 한다.
- **닫기 시점:** 다음 영업 시작 시각까지 기다렸다 닫는다. 종료 직후에 닫으면 아직 앉아 있는 손님 세션까지 닫히기 때문이다. 그래서 마감 직후 화면에는 아직 착석으로 보인다.
- **휴무일 미고려:** 다음 날이 휴무여도 영업 시작 시각에 닫힌다. 결과(퇴점 시각)는 같다.
- **도면 좌표 오차:** 34cm 칸 반올림으로 최대 약 17cm다.
- **방문 목적·관계 선택지:** PROVISIONAL이다. 사장님 확인이 필요하다.
- **성별 수집:** 익명 선택값이지만 기기 쿠키와 함께 저장된다. P-15 법률 검토 범위에 들어간다.
- **사용하지 않는 `PixelFloorMap.tsx`:** 약 1100줄이 남아 있다.
