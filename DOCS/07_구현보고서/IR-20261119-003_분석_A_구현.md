# S06 분석 목업 A 구현

## 구현

- `frontend/src/pages/AnalyticsPage.tsx`: 기간 버튼·날짜 범위, 매출·영업이익·객단가·목표, 시간대 판매 막대, 성별 clipPath 실루엣, 연령 비중, 관계별 TOP3, 메뉴 단상·판매량/마진액 전환, 날씨별 메뉴를 연결했다.
- `frontend/src/styles/analytics.css`: 목업 A의 간격·색상·카드·단상·막대를 .analytics-page 내부 @layer components에 적용했다. kpi.css 토큰과 useAnimatedNumber를 재사용하며 기존 막대 전환 900ms와 reduced-motion 처리를 보존했다.
- 기존 판매·객층·월 손익·일 손익·오늘 요약 조회만 사용한다. 계산 분모가 없거나 조회 실패 시 미산출을 표시한다. 실패 안내와 재조회 버튼을 추가했다.
- 주간 손익은 서버의 weekly.current, 월간은 monthly_average.current를 사용한다. 오늘 손익은 일 상세 기준으로 월 고정비 제외를 명시한다. 객단가는 매출/방문 인원이며 주·월 방문 인원 미제공 시 미산출이다.
- 누적 판매·객층·관계·날씨에는 기간 필터 계약이 없어 화면에 전체 기록 기준을 명시했다. 모든 기간의 영업이익을 6개월 trend로 대체하지 않았다. 마진액은 허용 API에 원가 계약이 없어 미산출로 유지한다.
- 전체 기간 시작일은 제공되지 않아 날짜를 꾸미지 않고 전체 기록·오늘까지로 표시한다. 시간대 값은 방문 수가 아니라 판매 수량으로 표시한다. 관계 TOP3의 시간 중첩 매칭은 추정으로 명시한다.

## 검사와 제약

- frontend의 `npx.cmd tsc --noEmit`, `npx.cmd eslint src/pages/AnalyticsPage.tsx --max-warnings 0` 통과. 로컬 node 엔트리 직접 실행도 동일하게 통과했다.
- 정적 self-review에서 누락/오류/분모 0, 미등록 목표, 100% 초과 목표 시 게이지 범위 제한, 메뉴 3개 미만, 관측 미설정과 순위 미산출 경로를 확인했다. 런타임 테스트 결과로 주장하지 않는다.
- 사용자 지시에 따라 장시간 테스트, 빌드, 브라우저 검증, 새 서버 실행은 생략했다. 목업 HTML과 1280 PNG는 읽었으나 실제 화면의 픽셀 일치와 런타임 무오류는 미검증이다.
- 백엔드·데이터·금지 파일·의존성은 변경하지 않았다. 기존 공유 체크아웃 변경을 보존했다. 커밋·push·배포 없음. POS 실연동 검증 없음.
- WO/IR/REV, 현재 인수인계·허브·변경이력을 갱신했다. 다음 확인은 기존 5174/8001에서 네 기간·빈 매장·조회 실패·1280/모바일 화면의 수동 검증이다.
