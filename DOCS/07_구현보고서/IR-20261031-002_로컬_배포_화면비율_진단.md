# IR-20261031-002 — 로컬/배포 화면 비율 진단

## 요청과 확정 사실
사용자: 같은 브라우저의 로컬100%에서 맞던 화면이 배포에서는 약67% 필요. Lenovo IdeaPad Flex5. 실제 비교 화면/브라우저 이름의 추가 답변 대기.

제품 코드·디자인·DB·공개 설정은 변경하지 않았다. 앞선 배포 diff에 전체 zoom/transform/기본 폰트 크기 변경 없음. 두 홈 화면 rootFont16px, body zoom1/transform none, 폰트 로드 완료.

## 실제 측정 (ego-lite 새 비교 Space6)
- 동일 창 outer1280×672, screen1280×720.
- 로컬 localhost:5173/home: inner1280×595, DPR1.5. 이 창에서는 브라우저100%에 해당.
- 외부 /food/home: inner1707×794, DPR1.125. 같은 OS 배율에 대한 비율0.75로 이 창의 해당 도메인 확대율은 약75%에 해당. **이 값이 사용자가 말한 원래100% 증상을 재현했다는 뜻은 아님.**
- 로컬/배포 stylesheet의 규칙 수·CSS text 차이는 있으나 production minify 정규화 차이와 일치. raw 문자열 diff만으로 스타일 버그라고 판단하지 않음.

## 동일 viewport 검사
`.deploy/layout-20261031-frame.mjs`로 각 페이지의 현재 렌더링된 root DOM과 CSS를 일시적인 iframe(1280×595)에 복제해 CSS viewport를 동일하게 맞췄다. React viewport 조건의 새 렌더를 검증하는 검사는 아니며 현재 홈의 CSS 레이아웃 비교다. 도메인 zoom별 scrollbar 폭 차이를 제외하기 위해 비교 프레임에서 overflow hidden 처리. 프레임은 측정 후 제거.

| 지표 | 배포 | 로컬 |
|---|---|---|
| root font | 16px | 16px |
| header width | 1280px | 1280px |
| main width | 1248px | 1248px |
| 도트 홀 width | 799.708px | 799.719px |
| 도트 홀 height | 726.667px | 729.333px |

배포가 약1.5배 커지는 현상은 재현되지 않았다. 차이는 1% 이내이며 zoom별 device-pixel 반올림 차이 범위. 초기 엄격1px 비교는 scrollbar·반올림 차이도 실패 처리해, user 증상(약50% 차이)을 검출하는 1% 높이/1px 너비 허용으로 검증. **MATCHED_VIEWPORT_LAYOUT_PASS**.

## 가설과 남은 확인
1. 도메인별 저장 확대율: 실제 측정에서 두 주소 배율이 다름. 사용자의 원래100% 비교 상황과 일치하는지 확인 필요.
2. 실제 브라우저 content viewport/창 크기/사이드 패널 차이: CSS viewport가 같다면 비율 차이가 사라져야 함.
3. 비교한 화면/도트 모드/상태 차이: 같은 URL/모드로 비교 시 차이가 사라지는지 확인 필요.

현재 사용자 증상의 정확한 원인은 미확정. 비교한 화면 및 브라우저 이름을 질문했고, 필요하면 두 화면100% 상태 자료를 받아 재현해야 한다. 현재 근거로 강제67% CSS 축소 또는 반응형 재설계를 적용하면 정상 로컬 화면도 바뀔 수 있으므로 수정하지 않았다. 임시 CDP viewport override는 모두 제거. DB/API 테스트는 변경이 없어 재실행하지 않음.

## 후속 요청에 따른 구현 (앞선 진단 결론의 변경 사유)
사용자가 이전 확대율을 잘못 기억했을 수 있다고 답하고, 노트북100%에서67% 크기로 보도록 명시 요청했다(U-15). 위 절은 요청 이전의 진단 기록이며 이후 비교 화면 답변 대기는 종료했다. 배포 버그로 단정하지 않고 사용자 선호에 따른 밀도 변경으로 진행.

- S00~S07 공통 `index.css`: viewport 너비1024~1535px·높이900px 이하·pointer:fine일 때 body zoom0.67. 기본폰트16px 및 기존 와인/Pretendard/도트 홀 유지. 모델명·해상도 비율 고정 방식 아님.
- `App.tsx`, `PixelFloorMap.tsx`, `HomePage.tsx`: 공통 `--app-viewport-height`로 CSS zoom에 맞춰 앱/홀 최소 높이, 주문 팝업90% 최대 높이 보정. 모바일·터치 전용 기기·큰 모니터에는 기존 크기. 별도 패키지/DB/API/인증 변경 없음.
- CSS zoom은 브라우저 배율을 변경하지 않으며 media breakpoint까지 브라우저67%와 같아지는 것은 아니다. 실제 사용 시 브라우저100% 기준. 1535px 경계에서 기존 크기로 돌아가는 것은 의도한 적용 범위.
- 변경 접점 검색: 전체 src의 vh/screen/fixed를 확인하고 viewport 높이를 쓰는4곳 모두 갱신. 나머지 fixed inset 팝업은 zoom된 좌표에서도 viewport 전체를 덮는지 실측.
- 노트북1280×595 screenshot에서 홀6개·방문 입력 패널·주문 열기 버튼 동시 노출. 폰390에서는 기존 세로 배치,1920에서는 기존 크기 유지. 도트 장식의 작은 글씨·다색·그림자는 기존 디자인 예외이며 재설계하지 않음.
