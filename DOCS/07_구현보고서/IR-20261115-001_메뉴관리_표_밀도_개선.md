# 메뉴 관리 표 밀도 개선

S03 / REQ-005·REQ-007. 기준 `design/astryx-menu`의 `a77bbfa`, 작업 브랜치 `t3/menu-management-table-redesign`.
작업 폴더: `C:\Users\leeej\.t3\worktrees\food\t3-612c8909-34ed1adb9891931f`.

## 구현

- 전체 버튼을 요약 카드와 합쳤다. 유형 버튼은 44px 높이의 한 줄이며 왼쪽부터 붙는다. 유형 추가와 입력 폼도 같은 줄에서 동작한다. 넘치면 가로 스크롤, 스크롤바 숨김과 끝 페이드를 적용한다.
- 검색 바로 옆에 판매 상태 필터를 두고, 메뉴 추가는 표 툴바 오른쪽으로 옮겼다. 제목 줄 버튼은 제거했다.
- 넓은 화면(너비 768px 이상, 높이 600px 이상)에서 페이지 높이는 `calc(var(--app-viewport-height) - var(--app-header-height, 56px) - 3rem)`이다. `3rem`은 App의 내용 래퍼 `pt-3`(0.75rem) + `pb-9`(2.25rem)이다. 제목·유형 줄·툴바·하단 페이지 탐색은 줄어들지 않고, 표가 flex로 나머지 공간을 채운다. 행이 적어도 빈 공간을 유지한다.
- 표의 Astryx 스크롤 래퍼만 세로 스크롤하고 헤더 셀은 고정한다. 좁거나 낮은 화면은 일반 문서 스크롤로 돌아간다. 기존 body zoom·뷰포트 변수는 변경하지 않았다.
- 페이지당 **20행**을 클라이언트에서 자른다. 필터·매장 변경 시 첫 페이지로 돌아간다. 삭제 등으로 줄어든 목록은 유효한 마지막 페이지로 보정한다. 번호·접근성 행 위치는 전체 조회 결과 기준이다.
- no·관리는 48px·64px, 나머지는 이름 1.5 : 종류·가격·운영·레시피 각각 1의 가변 비율과 내용별 최소 폭을 사용한다. 가격 포함 모든 열은 왼쪽 정렬이다.
- Astryx Switch의 `changeAction`과 행별 임시 상태로 손잡이·문구를 즉시 변경한다. 저장 후 재조회까지 기다린 뒤 확정한다. 실패는 다시 던져 Switch가 복구하도록 하고 임시 문구를 원복하며 오류 토스트를 표시한다. 전환 시간은 180ms, 동작 줄이기 설정에서는 CSS transition·animation을 끈다.
- 레시피는 완료·등록중·미등록을 chip-ok·chip-warn·chip-idle 버튼으로 표시한다. 접근성 이름에는 메뉴명과 상태를 포함한다. 버튼은 기존 RecipeEditorModal을 열고 별도 보기 버튼은 제거했다.
- 메뉴 추가·수정·삭제·비활성화·유형 추가·필터·검색·레시피 저장 경로는 유지했다. 모달·백엔드·API·의존성·홀 화면은 변경하지 않았다.
