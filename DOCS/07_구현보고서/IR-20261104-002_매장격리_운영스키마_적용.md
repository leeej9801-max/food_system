# IR-20261104-002 — 매장 격리(ADR-013 B안) 운영 스키마 적용

## 1. 구현 범위
[[ADR-013_매장격리_B안_앱계층_RLS]]를 실제 스키마·API·배포 구성에 적용. **실행 중인 공개 데모(`/food`)에는 아직 배포하지 않음** (사용자 확인 후, 순서는 `deploy/README.md` "매장 격리").

## 2. 변경 파일
- `backend/app/db/tenancy.py`: `bind_store_scope`(세션에 `RequestContext`를 묶음) + SQLAlchemy `after_begin` 이벤트로 **트랜잭션이 새로 시작될 때마다** `set_config('app.current_store_id', …, true)` 재적용 (서비스 중간 `commit()` 대응). SQLite에서는 아무것도 하지 않음.
- `backend/app/db/session.py`: `get_db(request)`가 경로의 `store_id`로 범위를 묶음(`bind_request_scope`).
- `backend/app/services/menus.py`: 매장 생성 직후 새 매장 범위로 전환(초기 테이블·감사 로그가 RLS를 통과).
- `backend/app/db/models/__init__.py`, `backend/app/services/ingredients.py`: `RecipeItem.store_id` 추가·저장.
- `backend/alembic/versions/0006_store_isolation_rls.py`: `recipe_items.store_id` 추가·레시피에서 채움·NOT NULL·FK·인덱스(SQLite는 batch). PostgreSQL에서만 `app_current_store_id()` 함수와 매장 테이블 15개 `ENABLE`+`FORCE` RLS, `store_isolation` 정책(text 비교, `USING`+`WITH CHECK`). downgrade 제공.
- `backend/scripts/ensure_runtime_role.py`: 런타임 계정 생성/비밀번호 갱신(`quote_literal`), DML 권한, `alembic_version` 권한 회수, 기본 권한.
- `backend/scripts/import_sqlite.py`: 0006 이전 SQLite 스냅샷(`recipe_items.store_id` 없음)도 가져오도록 레시피에서 채움. 소유자 계정으로 실행한다고 명시.
- `backend/scripts/prepare_deployment.py`: 기존 `.env.deploy`에도 `RUNTIME_DB_PASSWORD` 추가.
- `compose.yaml`: `migrate`=소유자 `food` + 런타임 계정 생성, `backend`=`food_app`. `deploy/.env.example`, `deploy/README.md` 갱신.
- `backend/tests/isolation/test_api_rls.py`: 실제 마이그레이션 + 런타임 계정으로 API 격리 테스트 6건.

## 3. 실행한 테스트 (실제 실행분)
- SQLite 전체: **24 passed, 14 skipped**, `ruff check .` 통과.
- PostgreSQL 17 일회용 컨테이너, `pytest tests/isolation`: **14 passed** (스파이크 8 + API 6).
- 변형 확인: 0006의 RLS 부분을 건너뛰게 하면 API 테스트 중 "범위 없는 DB 접근 0행" 1건이 실패하고 5건은 통과. API 수준 교차 접근은 앱 필터가 이미 막고 있고(이중 방어), RLS는 앱이 범위를 빠뜨린 경로를 막는다.
- **실데이터 마이그레이션:** 라이브 데모 DB를 `pg_dump`(읽기 전용)로 복사해 테스트 PG에 복원 → `0005 → 0006 → downgrade → 0006` 성공. `recipe_items` 9/9 매장 일치, RLS 테이블 15개, 런타임 계정 범위 없이 0행, 범위 지정 시 소유자와 같은 행 수(메뉴 5, 주문 147, 방문 15, 레시피 항목 9), 중간 `commit()` 후에도 범위 유지.
- **compose 리허설:** 별도 프로젝트 `food_rlscheck`(별도 볼륨·이미지 태그)로 라이브 복사본 복원 → `migrate`(0006 + "runtime role ready") → `backend` healthy(`food_app` 접속). API 8개 경로 데이터 조회 정상, 새 매장 생성 시 테이블 2·메뉴 0으로 격리. 리허설 스택·볼륨·이미지는 삭제.
- SQLite 개발 DB 복사본에서도 upgrade/downgrade/upgrade 성공, 9/9 일치.
