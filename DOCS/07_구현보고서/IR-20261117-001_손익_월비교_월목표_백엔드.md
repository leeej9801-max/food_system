# 손익 월 비교·월 목표 백엔드

사용자의 백엔드 구현 지시를 `design/pnl-ux` 공유 체크아웃에서 수행했다. REQ-013 감사 기록, U-24 손익·목표 확장, ADR-013 매장 격리와 동기 3계층 구조를 유지했다.

## API 계약

기존 `PnlResponse`에 다음 두 필드를 추가했다. 아래 date는 JSON에서 `YYYY-MM-DD` 문자열, int는 원 단위 정수다.

```text
comparison: {
  previous_month: {
    month: str,
    revenue: int,
    total_expenses: int,
    operating_profit: int
  },
  to_date: {
    start: date, end: date,
    revenue: int, expenses: int, operating_profit: int
  } | null,
  previous_to_date: {
    start: date, end: date,
    revenue: int, expenses: int, operating_profit: int
  } | null
}
goal: { revenue_target: int | null, profit_target: int | null }
```

- `previous_month`는 항상 `trend[-2]`를 재사용한다. 수기 월 항목 및 자동 항목을 반영한 지난달 전체다.
- 조회 월이 매장 timezone 기준 현재 월일 때만 두 누계를 반환한다. 시작·종료 날짜는 양 끝 포함. 지난달은 오늘과 같은 일자로 자르되 그 달 말일을 넘지 않는다.
- 누계는 기존 `_daily`의 일별 반올림 결과를 합한다. 날짜가 없는 월 수기 매출·비용을 제외하며, 비용은 날짜가 있는 식자재 입고와 카드수수료만 반영한다. 따라서 월 전체 손익과 직접 같은 계산 기준으로 보지 않는다. `PnlPeriod` 한 줄 docstring에 명시했다.
- API 시각 의존성 `Depends(utcnow)`와 서비스 `now` 인자로 테스트 시각을 고정한다. HTTP 사용자가 시각을 변경하는 쿼리 파라미터는 추가하지 않았다.
- `PUT /api/v1/stores/{store_id}/pnl/{month}/goal`은 `{revenue_target?, profit_target?}`를 받고 전체 `PnlResponse`를 반환한다. 생략한 필드는 null로 저장하는 전체 대체 방식이다. 매출 범위 0~10,000,000,000, 이익 범위 -10,000,000,000~10,000,000,000. 모두 null이면 행을 보존한다.
- 목표 변경은 같은 트랜잭션에서 `entity_type=monthly_goal`, 해당 행 ID, 월·두 목표 값으로 감사 기록을 남긴다.

## 저장 구조

`0014_monthly_goals`는 `0013_weather_daily` 다음 리비전이다. uuid PK, 매장 RESTRICT FK, char(7) 월, nullable bigint 목표 2개, timezone-aware 생성·수정 시각, 매장·월 고유 제약을 만든다. PostgreSQL `ON CONFLICT DO UPDATE`로 동일 매장·월의 저장을 한 문장으로 처리한다.

`monthly_expenses`와 같은 ENABLE/FORCE RLS 및 `store_isolation` USING/WITH CHECK 정책을 적용한다. 런타임 권한은 기존 `ensure_runtime_role`의 기본 권한 패턴을 따른다. 개발 DB `food_dev`에 upgrade head를 적용했고 리비전·컬럼 타입·RLS 활성/강제·정책 이름을 직접 조회해 확인했다. 운영 DB에는 적용하지 않았다.

## 검증

테스트 환경은 사용자가 지정한 로컬 PostgreSQL 일회용 DB다. 테스트 DB는 기존 fixture가 Alembic으로 생성하고 NOBYPASSRLS 런타임 계정으로 API를 호출한다. 비밀값은 문서에 기록하지 않는다.

OpenAPI diff는 새 손익 스키마 4개·응답 필드 2개·목표 PUT 경로에 한정된다. 생성 fixture의 손익 표본 2개에서 목표 null/설정값, 10월 1~15일 비교 기간을 확인했다. `git diff --check`도 통과했다. 문서 링크 검사는 기존 `WO-20261110-002`의 `WO-20261110-001_손님_모바일웹_및_매장TV_시안` 참조 1건이 깨져 있고, 이번 작업의 신규 링크 오류는 없다.

## 미검증·범위

프론트 화면·브라우저·실기기, 운영 DB 적용, POS A/B 실연동은 미검증이다. 기존 전체 매출을 카드 매출로 간주하는 수수료 계산 가정은 그대로 유지한다. 신규 스키마의 downgrade 및 동시 요청 부하 테스트는 실행하지 않았다.

프론트 소스는 생성 fixture 외에는 수정하지 않았다. 공유 체크아웃의 다른 작업 변경과 package/lock/skills 파일을 건드리지 않았다. backend/.env 변경, commit, push, 추가 위임은 하지 않았다.
