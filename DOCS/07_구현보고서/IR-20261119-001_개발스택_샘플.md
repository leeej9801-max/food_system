# 개발 스택 복구와 통합 샘플 검증

- 로컬 이미지의 Uvicorn 자식이 httpx import 오류로 종료됐다. cdb733a에서 httpx/PyJWT가 들어간 기존 잠금 파일을 Dockerfile이 이미 사용한다. 로컬 전용 Compose에 backend 빌드 경로를 지정했다.
- `docker compose -f compose.dev.yaml build backend` → `docker compose -f compose.dev.yaml up -d --no-deps --no-build --force-recreate backend`를 실행했다. 개발 백엔드 1개(8001), 기존 food-rls-test(55432)를 확인했다. 이미지의 httpx/PyJWT는 0.28.1/2.15.1이다.
- `docker exec food-dev-backend-1 alembic heads`에서 단일 head를 확인한 뒤 같은 컨테이너에서 `alembic upgrade head`와 `alembic current`를 실행했다. food_dev는 0014_monthly_goals에서 0017_staff_kakao_qr로 올라갔다.
- `curl.exe http://localhost:8001/api/v1/stores`는 200. 동일 매장의 메뉴·식자재·재고·손익(월 지정)·근태(기간 지정)·판매·방문·테이블 API는 200. 5174는 리스너가 없어 브라우저 확인을 생략했다. API는 5174 Origin을 허용한다.
- 기존 태그로 식별된 샘플 매장은 하나였다. 시드 호출 전 판매 4,093, 메뉴 4, 식자재 5, 입고 865, 실사 30, 월 비용 84, 방문 4,093, 슬롯 7,683이었다. 직원·근무 일정·도면 고정물은 모두 0.
- 동일 매장의 시드 API를 호출하여 판매/방문 각각 4,115, 메뉴 4, 식자재 5, 입고 870, 실사 30, 월 비용 84, 슬롯 7,721, 직원 2, 근무 일정 26, meal_love 고정물 9를 확인했다. 실제 출퇴근 이벤트나 손님 식별 정보는 시드하지 않는다.
- 기존 위저드 기본 배치의 축약 좌표는 도면이 추가되면 테이블이 겹쳐 보이므로 도면 좌표로 바꾼다. 테이블 ID·방문 참조는 보존한다. 수정한 테스트는 기본 배치와 빈 매장, 재호출, 수기 데이터 보존을 확인한다.
- 변경 파일은 demo_seed.py와 백엔드 API 테스트다. 운영 컨테이너·운영 Compose·운영 환경 파일 및 프론트 패키지 파일을 수정하는 작업은 수행하지 않았다. 실제 POS·카카오 연동은 미검증이다.

## 검증 결과

- PostgreSQL 격리 DB 및 역할로 기존 API 테스트 7개 통과. 기존 위저드 좌표 보강 후 관련 시드 회귀 2개 재실행 통과. Ruff 및 Pyright 검사 통과.
- 개발 API로 같은 날 다시 시드했다. 테이블 ID 6개와 직원·일정·도면 수가 유지됐으며 기존 위저드 배치의 T1 좌표는 (21, 1, V)로 바뀌었다.
- Vault 링크 검사에서 기존 리팩터링 문서의 깨진 링크 1개를 확인했다. 이번 작업에서 추가한 링크 오류와 중복 문서 이름은 0개다.
