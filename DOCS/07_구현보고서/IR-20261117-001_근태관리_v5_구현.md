# IR-20261117-001 — 근태 관리 v5 구현

## 1. 구현한 요구사항 / 화면 / 결정 ID

사용자 지시 1~7, U-24, ADR-014, 인증 설계 §6.4를 기준으로 구현했다. 기존 S00~S07 번호를 임의로 확장하지 않았다. 작업은 `C:/Users/leeej/.t3/worktrees/food/feature-attendance`, `feature/attendance`에서만 진행했다. 본 저장소 파일, 금지 경로, manifest/lock, `.env`는 수정하지 않았다. 커밋·stage·push·배포는 하지 않았다.

- 사이드바 `근태 관리`, `/attendance`, 기존 매장 query 유지. 기존 셸과 Dialog, Astryx Theme/Button/Tooltip, React Query, zod API 경계를 재사용한다.
- 직원 등록·목록: 이름, 홀/주방, 색. 직원 칩 클릭 시 선택 직원 강조, 나머지 불투명도 0.28. 시급·인건비 필드는 없다.
- 일간: 0~24시 축, 전체 근무 막대 양끝 30분 드래그, 최소 1시간. 화살표 키로도 30분 조절한다. 실제 출퇴근 막대와 선택 날짜의 현재 시각선을 표시한다.
- 주간: 월~일, 명단 칩 드롭 후 기간 확장 핸들, `시간 설정하기`, 모달 저장. 빈 칸 추가와 확장 핸들 키보드 조작을 제공한다.
- 월간: 실제 달력 요일, 날짜 드롭 후 모달, 저장된 근무 칩 편집. 휴무는 `store.business_days`를 사용한다.
- 시간 모달: 수동 설정을 맨 왼쪽 기본값으로 두고 오전/오후/오픈/마감 프리셋을 제공한다. 이름·시간 유형 편집을 서버에 저장한다. 오전·오후/시/분 스크롤 스냅 휠과 화살표 키, 퇴근 > 출근 및 최소 1시간 검증, 24:00 퇴근 선택을 제공한다.
- 날짜 pill 바로 아래 작은 달력. 일자 선택 시 현재 탭 기준 날짜/월~일 주/월이 바뀐다. ‹ ›와 오늘, 하단 카드의 기간이 같은 날짜 상태를 사용한다.
- 점주 근무는 직원 원본 기록과 분리한 스케줄(`staff_id=null`)이다. 요청한 툴팁을 제공하고 공백 계산에서 제외한다.
- 출퇴근 직접 등록은 **PROVISIONAL**이다. POST는 클라이언트 시각을 받지 않고 서버 UTC 시각을 기록한다. 중복 IN/OUT, 역전된 순서와 동일 시각을 거부한다.
- 수동 수정: 직원·기록 선택, 출근/퇴근 일시, 원본 표시, 필수 사유, 원본·정정 전체 이력. 로그인 미구현 비밀번호 재확인은 disabled 자리와 PROVISIONAL 문구만 제공한다.
- 원본 `attendance_events`와 추가 전용 `attendance_corrections`를 분리한다. 누락 추가의 재정정은 `previous_correction_id`로 연결한다. 직원/원본 매장 범위와 UTC를 검증하고 마지막 정정을 투영한다. 원본 UPDATE/DELETE API는 없다.
- 일별 실제 시간·근무 전체 시간·초과분을 결정론적으로 집계한다. 누락 시간은 미산출로 분리한다. 직원별 숫자 오른쪽 마지막 ⓘ에 `근무 전체 시간 Xh · 초과 Yh`를 표시한다.
- 공백은 영업시간에서 직원·점주 스케줄의 합집합을 빼서 계산한다. 휴무 제외, 야간 영업은 다음 날 스케줄까지 포함한다. 영업 설정이 없으면 계산 불가를 안내한다.

## 3. 실행 명령 / 환경 변수 (비밀 값 제외)

`backend`에서 `uv sync --extra dev`, `frontend`에서 `npm ci`를 실행했다. 의존성 파일은 변경하지 않았다.

실제 사용할 DB에 적용할 때는 백업·권한 있는 소유자 연결을 준비한 뒤 `alembic upgrade head`와 런타임 역할 설정을 수행한다. 이번에는 운영 DB를 변경하지 않았다.

로컬 확인은 임시 SQLite QA DB와 가상 이름 `QA 1~4`만 사용했다. 샘플은 제품 코드에 넣지 않았다. 서버는 요청대로 backend 8002, frontend 5175를 사용했다. `VITE_API_BASE_URL=http://localhost:8002/api/v1`, CORS도 5175로 설정했다. 캡처용 QA DB는 사용자 임시 폴더에 있다.

```powershell
# backend (DATABASE_URL은 환경별로 설정)
.venv/Scripts/python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8002
# frontend
$env:VITE_API_BASE_URL='http://localhost:8002/api/v1'
npm.cmd run dev -- --host 127.0.0.1 --port 5175 --strictPort
```

## 5. 시안과 다른 점 / 미구현 / 이유

- 시안 HTML/CSS와 지정 PNG 4장을 실제로 열어 보고 이식했다. 새 디자인 추첨은 하지 않았다. 기존 앱 상단 공통 헤더·사이드바 아이콘은 유지하므로 시안보다 본문 시작이 아래다. 주간에 점주 근무를 조회·편집할 행이 하나 더 있다.
- 샘플 수치·이름·11월 일정 패턴을 하드코딩하지 않았다. 카드·누락·휴무·실제 막대는 선택 기간과 실제 QA API 응답을 사용한다. 시안의 하단 카드 날짜가 선택 기간과 다른 부분은 요청대로 일치시켰다.
- QR·소셜·기기 등록 UI는 없다. 점주 직접 등록/재인증 미구현을 PROVISIONAL로 표시했다. 인증 완료로 해석하면 안 된다.
- 모달은 Astryx 버튼과 기존 native Dialog로 키보드·Esc·포커스 복귀를 제공한다. 분 휠은 30분 단위이고 24:00 선택을 추가했다. 유형 편집은 서버에 저장한다.
- 스케줄은 하루 0~24시 내 한 건이며, 날짜를 넘는 근무는 현재 두 날짜로 나누어 입력한다. 실제 출퇴근 기록·정정은 날짜를 넘을 수 있으며 기간 경계로 나누어 집계한다. 단일 야간 스케줄 UX는 아래 질문이다.
- 초과는 휴게를 빼지 않은 일별 실제 시간 − 일별 계획의 양수 합이다. 수당·법적 연장근로 계산이 아니다. 누락 구간은 0시간 확정이 아닌 미산출로 표시한다.
- 월간은 직원 칩을 모두 표시하므로 직원·근무가 많으면 칸과 페이지 높이가 커질 수 있다. 1280 화면에서 원본 시안과 동일한 픽셀 단위 일치를 주장하지 않는다.

## 6. POS 연동 / 검증 범위
