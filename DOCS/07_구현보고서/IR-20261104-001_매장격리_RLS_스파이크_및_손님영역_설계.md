# IR-20261104-001 — 매장 간 데이터 격리(B안) 스파이크 + 손님 영역 설계 문서

## 1. 구현한 결정 / 문서
- 결정 U-16~U-22, ADR-013 (인터뷰 8회차).
- 설계: [[ADR-013_매장격리_B안_앱계층_RLS]], [[손님영역_흐름정의_및_ERD_초안]], [[개인정보_처리설계_초안]].

## 2. 변경 파일
- `backend/app/db/tenancy.py` (신규): `RequestContext(store_id, actor)`, `authorize`(베타는 모두 허용), `apply_store_scope`(트랜잭션 단위 `set_config('app.current_store_id', …, true)`). 기존 라우트·서비스에는 아직 연결하지 않음.
- `backend/tests/isolation/rls_policies.sql` (신규): 별도 `rls_spike` 스키마. 전역 테이블(`guest_profiles`, `characters`)과 매장 테이블(`store_tables`, `visit_sessions`), fail-closed 정책, `ENABLE`+`FORCE` RLS, 런타임 계정 권한.
- `backend/tests/isolation/test_rls_isolation.py` (신규): PostgreSQL 전용 격리 테스트 8건. `RLS_TEST_DATABASE_URL` 없으면 skip.
- `backend/scripts/rls_benchmark.py` (신규): 100만 행에서 RLS 유/무 같은 쿼리 비교.
- DOCS: WO/IR/REV/TEST, 결정사항_로그(U-16~U-22, ADR-013), 인터뷰_기록 8회차, `10_설계/` 문서 3건, 인수인계·변경이력·허브.

## 3. 실행 명령 (비밀 값 제외)
```powershell
docker run -d --rm --name food_ax_rls_spike -e POSTGRES_USER=spike_owner -e POSTGRES_PASSWORD=<로컬 임시 값> -e POSTGRES_DB=rls_spike -p 127.0.0.1:55432:5432 postgres:17-alpine
cd C:\dev\food\backend
$env:RLS_TEST_DATABASE_URL = "postgresql+psycopg://spike_owner:<로컬 임시 값>@127.0.0.1:55432/rls_spike"
uv run pytest tests/isolation -v
uv run python scripts/rls_benchmark.py
docker stop food_ax_rls_spike
```

## 4. 실행한 테스트와 결과 (실제 실행분)
- PostgreSQL 17(일회용 Docker 컨테이너)에서 `pytest tests/isolation -v`: **8 passed**.
- 변형 확인: 정책 SQL에서 `ENABLE`/`FORCE ROW LEVEL SECURITY` 4줄을 임시로 지우고 실행 → **7 failed, 1 passed**(전역 테이블 테스트만 통과, 기대대로). 이후 원복.
- 전체 `pytest`(PostgreSQL URL 설정): **32 passed**. URL 없이: **24 passed, 8 skipped** (기존 SQLite 테스트 회귀 없음).
- `ruff check .`: 통과.
- 벤치마크 2회 (50개 매장 × 2만 = 100만 행, 한 매장 30일 시간대별 집계, 30회 중앙값): A안 39.09 / 36.35 ms, B안 39.05 / 36.59 ms, RLS만 42.35 / 35.51 ms. 측정 오차 안에서 차이 없음.

## 5. 미구현 / 차이
- 운영 스키마·기존 API에 RLS 미적용(비범위). 적용 시 필요한 일은 ADR-013 §5.
- 운영 ID는 `String(36)`, 스파이크는 `uuid` 컬럼 — 적용 시 정리 필요.
- 테스트 컨테이너 소유자가 슈퍼유저라 "비슈퍼유저 소유자 + FORCE" 경우는 미확인.
