## 3. 데이터 파이프라인 무결성 보완 및 코드 최적화 내역

### 3.1 파이프라인 순서 독립성 확보 (선 CSV 업로드 → 후 메뉴 등록 시 자동 소급 연결)
- **문제점:** 기존에는 메뉴를 먼저 등록한 뒤 CSV를 업로드하면 자동 매칭되었으나, **CSV를 먼저 업로드(`UNMAPPED`)한 뒤 나중에 S03에서 동일 이름의 메뉴를 신규 등록하거나 이름을 수정**하면 사용자가 S01에서 수동으로 다시 매핑해야만 S05(이론 소모량)·S06(매출 집계)에 반영되었다.
- **해결 (`backend/app/services/menus.py`):**
  - `_retroactive_link_unmapped_sales(db, store_id=..., menu_item=...)` 함수를 추가하여, 메뉴 생성(`create_menu`) 및 수정(`update_menu`, 활성 상태일 때) 시 해당 점포의 `UNMAPPED` `SalesOrderItem` 중 정규화 상품명(`.strip().casefold()`)이 일치하는 항목을 즉시 `MAPPED` 및 `menu_item_id`로 소급 연결하도록 개선했다.
  - 또한 `get_linked_menu_ids`를 통해 실제 `PosProductMapping` 또는 매칭된 `SalesOrderItem`이 존재하는 메뉴는 `pos_mapping_status = "LINKED"`, 아직 없는 메뉴는 `"UNLINKED_PROVISIONAL"`을 반환하도록 고도화했다.

### 3.2 Excel UTF-8 BOM(`\ufeff`) 방어 및 대소문자·공백 정규화 통일
- **문제점:** Windows Excel에서 저장한 `UTF-8 CSV` 파일은 첫 바이트에 `\ufeff` (BOM)가 포함되어 첫 번째 헤더(`주문번호`) 인식이 깨질 수 있으며, 메뉴명 대소문자나 앞뒤 공백 차이로 자동 매칭이 누락될 수 있었다.
- **해결 (`backend/app/services/imports.py`):**
  - `preview_sales_csv`에서 `csv_text.lstrip("\ufeff")` 및 헤더 키 `.lstrip("\ufeff")` 처리를 추가했다.
  - `_build_menu_lookup`, `preview_sales_csv`, `commit_sales_csv`, `upsert_product_mapping` 전반에서 `.strip().casefold()` 기준 정규화 매칭을 일관되게 적용했다.

### 3.3 실재고 실사 이후 과거 날짜 CSV 지연 업로드 시 재고 차감 오염 방지
- **문제점:** 사장님이 오늘(예: 10월 25일) 실재고 실사(`InventoryCount`)를 입력한 뒤, 어제(10월 24일)자 마감 CSV를 뒤늦게 업로드하면 `order.received_at`은 실사 시각 이후이므로 어제 판매분이 오늘 실사 이후 예상 재고에서 중복 차감될 위험이 있었다.
- **해결 (`backend/app/services/inventory.py`):**
  - `get_inventory_summary`에서 `order.received_at <= baseline_dt` 조건에 더해 `item_ord_dt.date() < baseline_dt.date()` 가드를 추가하여, 실사 기준일보다 과거 영업일의 판매 데이터는 실사 이후 재고에서 차감되지 않도록 방어했다.

### 3.4 백엔드 N+1 쿼리 제거 및 `O(N)` 인메모리 인덱싱 최적화
- **`backend/app/services/imports.py` (`commit_sales_csv`):** 주문 건마다 개별 실행하던 `SELECT ... FROM sales_orders WHERE external_order_id = ...` 쿼리를 `external_order_id IN (...)` 단일 배치 조회로 변경했다.
- **`backend/app/services/ingredients.py` (`upsert_menu_recipe`):** 레시피 행마다 개별 실행하던 식자재 조회 쿼리를 `Ingredient.id.in_(...)` 단일 배치 조회로 변경했다.
- **`backend/app/services/inventory.py` (`get_inventory_summary`):** 식자재 수 × (입고 + 실사 + 보정 + 판매) 중첩 루프(`O(I * (R + C + A + S))`)를 사전 인덱싱 딕셔너리(`receipts_by_ing`, `counts_by_ing`, `adjustments_by_ing`, `ing_menu_qty`, `sales_by_menu`) 기반 `O(N)` 조회로 최적화했다.

### 3.5 프론트엔드 UI/UX 최적화
- **`frontend/src/pages/MenuManagementPage.tsx` (S03):** `pos_mapping_status === 'LINKED'`인 메뉴에 녹색 `● 연결됨 (POS/CSV)` 배지를 표시하여 파이프라인 연결 상태를 직관적으로 확인할 수 있게 했다.
- **`frontend/src/pages/AnalyticsPage.tsx` (S06):**
  - 테이블 확장 행의 React `<Fragment key={m.menu_item_id}>` 누락 경고를 수정했다.
  - 메뉴 레시피 상세 펼침 영역 안에서 **식자재별 개별 단가 변동률(%) 직접 입력칸**을 추가하여, 상단 원클릭 프리셋뿐만 아니라 특정 식자재 조합의 동시 단가 변동 시뮬레이션도 즉시 수행할 수 있도록 개선했다.
