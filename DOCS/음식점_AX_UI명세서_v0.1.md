# 음식점 AX 데이터 수집 서비스 — UI 명세서

- 문서 버전: v0.1 (초기 초안)
- 상태: 인터뷰를 통해 확정할 가정이 포함된 작업 문서
- 목표 사용자: 1~2인이 운영하는 신규·소규모 음식점
- 우선 구현: 웹 기반 PWA, 매장 운영 중 태블릿 사용
- 핵심 목표: 운영자가 같은 데이터를 여러 번 입력하지 않도록 하며, 자동 수집이 불가능한 데이터만 최소한의 조작으로 기록한다.

## 1. 제품 설계 원칙

1. **자동 수집 우선:** POS에 이미 존재하는 판매·상품 데이터는 가능한 한 자동으로 가져온다.
2. **한 번만 기록:** 입고·재고 실사·방문 기록 등 현장에서만 알 수 있는 정보만 필요한 시점에 입력한다.
3. **계산 결과는 입력하지 않는다:** 판매량·레시피·입고·폐기 데이터를 이용해 예상 재고와 메뉴 원가를 계산한다.
4. **모드별 분기는 수집 방식에 한정:** 토스 Open API, POS Plugin SDK, CSV/Excel 방식이 달라도 기본 데이터 모델과 화면 구조는 최대한 공통으로 유지한다.
5. **정보가 부족해도 업무를 막지 않는다:** 레시피·연령대 등 선택 정보가 없더라도 판매 데이터 수집은 지속된다. 미완성 데이터는 상태로 표시한다.
6. **데이터 원본과 이력을 보존한다:** POS 재수집·모드 변경·수정이 기존 기록을 덮어쓰거나 중복 집계하지 않도록 한다.
7. **빠른 현장 UX:** 영업 중 자주 쓰는 동작은 큰 버튼, 짧은 입력, 기본값, 최근 사용 항목을 활용한다.

## 2. 정보 구조 및 내비게이션

### 2.1 데스크톱/노트북

왼쪽 내비게이션을 기본으로 한다.

- 홈
- 메뉴 관리
- 식자재·레시피
- 입고·재고
- 분석 대시보드
- 설정

### 2.2 태블릿 PWA

현장 사용을 우선해 홈 화면에서 매장 조감도와 빠른 기록을 중심으로 제공한다. 주요 영역은 하단 탭 또는 고정된 간편 메뉴로 이동한다.

- 홈
- 빠른 기록
- 재고
- 분석
- 설정

메뉴·레시피의 대량 등록과 매장 기본 설정은 태블릿에서도 접근 가능하게 하되, 우선은 데스크톱 작업에 적합한 테이블형 UI를 제공한다.

## 4. 공통 상태 및 메시지

모든 자동 수집 데이터에 다음 상태를 일관되게 표시한다.

- 연결됨 / 연결 필요 / 연결 오류
- 마지막 정상 수집 시각
- 데이터 최신성: 최신 / 지연 / 업로드 필요
- 메뉴 매핑: 연결됨 / 미연결 / 검토 필요
- 레시피: 완성 / 일부 미입력 / 미등록

오류 메시지는 기술 코드만 표시하지 말고 사용자가 취할 수 있는 조치를 함께 제시한다. 예: “오늘 판매 파일이 아직 없습니다. CSV/Excel 파일을 업로드하세요.”

## 5. 화면 상세 초안

### S00. 매장 생성·초기 설정

**목적:** 매장별 설정을 프로젝트 생성처럼 단계적으로 등록한다.

**와이어프레임 초안**

```text
┌────────────────────────────────────────────┐
│ 새 매장 만들기                     1 / 4    │
├────────────────────────────────────────────┤
│ 매장명       [________________________]    │
│ 영업일       [월][화][수][목][금][토][일]   │
│ 운영시간     [11:00] ~ [21:00]              │
│                                            │
│ 테이블 구성                                │
│ 테이블 수 [ - ] 6 [ + ]                    │
│ 좌석 수는 테이블별로 나중에 조정할 수 있음  │
│                                            │
│ [이전]                         [다음 단계]  │
└────────────────────────────────────────────┘
```

**필드 초안**
- 필수: 매장명, 영업일, 운영시간, 테이블 수
- 테이블별 설정: 테이블명/번호, 좌석 수, 배치도 위치(초기 자동 배치 후 편집 가능)
- 선택: 직원 수, 조리/홀 역할별 인원, 주소, 매장 유형
- 직원 구성은 초기 데이터 수집 MVP에서 사용하지 않으면 생략 가능

**버튼/동작**
- `다음 단계`: 필수값 검증 후 다음 단계로 이동
- `건너뛰기`: 선택 항목만 허용
- `매장 생성`: 설정 저장 후 S01로 이동
- 뒤로 이동해도 기존 입력값 유지

### S01. POS 연결 및 데이터 수집 방식

**목적:** 대상 POS에서 가능한 수집 방식을 선택하고 연결 상태를 표시한다.

**와이어프레임 초안**

```text
┌────────────────────────────────────────────┐
│ 데이터 수집 방식                            │
├────────────────────────────────────────────┤
│ ( ) A. 토스플레이스 Open API                │
│     서버 API로 지원되는 주문/상품 데이터 수집│
│     [연결 설정] [연결 테스트]                │
│                                            │
│ ( ) B. 토스플레이스 POS Plugin SDK          │
│     POS 플러그인 이벤트를 서버로 전달        │
│     [설치/검수 안내] [연결 상태 확인]        │
│                                            │
│ ( ) C. CSV / Excel                          │
│     파일 업로드로 판매 데이터 가져오기       │
│     [샘플 양식 다운로드] [파일 업로드]       │
│                                            │
│ 현재 상태: 연결 방식 선택 필요              │
│ [이전]                           [저장]     │
└────────────────────────────────────────────┘
```

**규칙**
- A/B는 실제 자격 증명, 승인, 설치 등 공급자 요건이 충족되기 전까지 “연동 준비/테스트”로 표시하고 연결 완료처럼 표현하지 않는다.
- C 모드에서는 업로드 시 열·데이터 형식을 검증하고, 매핑할 수 없는 열을 사용자에게 확인받는다.
- 모드 변경 시 과거 데이터는 삭제하지 않는다.
- 동일 POS 주문/이벤트가 중복 집계되지 않도록 원본 식별자와 수집 이력을 기록한다.
- 지원 데이터 목록은 모드별로 표시한다. 예: 메뉴별 판매량 자동 수집 가능 / 테이블 매핑 미지원 / 방문 인원 수기 입력 필요.

### S02. 홈·매장 배치도

**목적:** 영업 중 매장 상태를 빠르게 확인하고 자동 수집되지 않는 값만 입력한다.

**와이어프레임 초안**

```text
┌────────────────────────────────────────────┐
│ 매장명     ● POS/파일 상태     오늘 14:32   │
├────────────────────────────────────────────┤
│ 오늘 매출*       방문 인원**      알림       │
│ 125,000원        12명             재고 2건  │
├────────────────────────────────────────────┤
│ 매장 배치도                                  │
│                                            │
│    [T1 · 2석]          [T2 · 4석]           │
│                                            │
│          [T3 · 4석]                        │
│                                            │
│    [T4 · 2석]          [T5 · 4석]           │
├────────────────────────────────────────────┤
│ [방문 기록] [테이블 비우기] [입고] [재고]   │
└────────────────────────────────────────────┘
```

`*` 매출은 POS/업로드 파일에 해당 정보가 있을 때만 표시한다. `**` 방문 인원은 기록된 값이며, 자동 수집 여부에 따라 집계 범위가 달라질 수 있음을 명시한다.

**테이블 선택 패널 필드 초안**
- 테이블 번호/이름, 좌석 수, 상태
- 착석 인원(필수/선택 여부는 인터뷰로 확정)
- 방문 시간 자동 기록
- 추정 연령대(선택, 기본값 미기록)
- POS 테이블/주문 연결 상태
- `착석 기록`, `수정`, `퇴점·테이블 비우기`

**규칙**
- POS에서 메뉴·주문을 가져올 수 있으면 메뉴 재입력을 요구하지 않는다.
- POS가 테이블 상태를 제공하지 않는 모드에서는 사용자가 테이블 상태를 관리할 수 있다.
- 결제 완료와 실제 퇴점은 별도 이벤트로 취급한다.
- 테이블 비우기는 현재 이용 세션을 종료할 뿐 과거 기록을 삭제하지 않는다.
- CSV 모드에서 파일에 테이블 정보가 없으면 메뉴별 판매는 수집할 수 있어도 테이블별 주문을 자동 연결할 수 없음을 표시한다.

### S03. 메뉴 관리

**목적:** 메뉴를 목록으로 관리하고 POS 상품 및 레시피와 연결한다.

**와이어프레임 초안**

```text
┌────────────────────────────────────────────────────────┐
│ 메뉴 관리                           [Excel 가져오기] [+ 메뉴 추가] │
├────────────────────────────────────────────────────────┤
│ 검색 [________] 카테고리 [전체 ▼] 상태 [전체 ▼]         │
├──────────┬────────┬──────────┬──────────┬──────────────┤
│ 메뉴명   │ 가격   │ POS 연결 │ 레시피   │ 관리         │
├──────────┼────────┼──────────┼──────────┼──────────────┤
│ 제육볶음 │ 12,000 │ 연결됨   │ 완성     │ [수정]       │
│ 김치찌개 │ 10,000 │ 연결됨   │ 일부 미입력│ [수정]       │
└──────────┴────────┴──────────┴──────────┴──────────────┘
```

**추가/수정 팝업 필드**
- 필수 후보: 메뉴명
- 선택: 판매가격, 카테고리, 설명, 판매 여부
- POS 연동 모드에서는 외부 상품과 내부 메뉴 매핑
- 레시피 영역: 식자재 선택, 1인분 사용량, 사용 단위, 재료 추가
- 비어 있는 항목도 저장 가능하되 상태를 “미입력”으로 표시

**규칙**
- POS에서 자동 수집된 상품을 메뉴 목록으로 가져오는 경우 중복 생성하지 않고 매핑 후보로 제시한다.
- 메뉴명만으로 자동 매칭을 확정하지 않는다. 모호한 경우 사용자 확인이 필요하다.
- 메뉴를 비활성화해도 과거 판매 내역은 보존한다.

### S04. 식자재·레시피 관리

**목적:** 식자재 마스터를 관리하고 메뉴와 식자재의 사용 관계를 설정한다.

**와이어프레임 초안**

```text
┌─────────────────────────────────────────────────────┐
│ 식자재·레시피 관리                 [Excel 가져오기] [+ 식자재 추가] │
├─────────────────────────────────────────────────────┤
│ 검색 [________] 분류 [전체 ▼] 등록 상태 [전체 ▼]    │
├──────────┬──────────┬────────────┬───────────────┤
│ 식자재명 │ 구매단위 │ 연결 메뉴 수│ 관리          │
├──────────┼──────────┼────────────┼───────────────┤
│ 돼지고기 │ kg       │ 3           │ [수정]        │
│ 양파     │ kg       │ 5           │ [수정]        │
└──────────┴──────────┴────────────┴───────────────┘
```

**식자재 추가/수정 팝업 필드**
- 필수 후보: 식자재명, 기본 단위
- 선택: 구매 단위, 사용 단위, 단위 변환값, 공급업체, 보관 메모
- 구매가격은 입고 거래에서 이력으로 기록하고, 마스터에는 최근 가격/기준 가격을 표시
- 연결 메뉴와 레시피 사용량 조회

**관계 관리 원칙**
- 메뉴 화면에서 레시피를 편집하든 식자재 화면에서 연결 메뉴를 편집하든 동일한 레시피 관계를 수정한다.
- 관계 데이터는 한 번만 저장한다.
- 식자재 이름이 비슷하더라도 자동 병합하지 않고 중복 후보로 제시한다.

### S05. 입고·재고 관리

**목적:** 구매 입고 기록, 구매가격 이력, 실재고 확인, 예상 재고 조회를 제공한다.

**와이어프레임 초안**

```text
┌──────────────────────────────────────────────┐
│ 입고·재고                 [+ 입고 기록] [실재고 입력] │
├──────────────────────────────────────────────┤
│ 식자재 검색 [________] 재고 상태 [전체 ▼]     │
├──────────┬──────────┬──────────┬─────────────┤
│ 식자재   │ 예상 재고│ 최근 단가│ 상태        │
├──────────┼──────────┼──────────┼─────────────┤
│ 돼지고기 │ 6.4 kg   │ 10,000/kg│ 확인 필요   │
└──────────┴──────────┴──────────┴─────────────┘
```

**입고 팝업 필드**
- 식자재 선택, 입고 수량, 구매 금액 또는 단가, 구매일, 공급업체(선택), 증빙 파일(선택)
- 기존 식자재 선택 후 수량·가격만 입력 가능
- 입고를 저장하면 재고 거래와 구매가격 이력을 추가한다. 기존 가격을 덮어쓰지 않는다.

**실재고 입력**
- 실제 측정 수량, 측정 시각 자동 기록, 메모(선택)
- 실재고와 예상 재고 차이가 크면 사유를 선택적으로 기록한다.

**계산 원칙**
- 예상 재고 = 기초 재고 + 입고량 - 레시피 기반 이론상 소비량 - 별도 식자재 폐기량 ± 조정량
- 실제 재고와 예상 재고는 별도 값으로 저장한다.

### S06. 데이터 분석 대시보드

**목적:** 실제로 확보된 데이터를 활용해 판매량·원가·재고를 분석한다.

**초기 위젯 후보**
- 일별/시간대별 메뉴 판매량
- 판매 데이터 최신 수집 시각 및 누락 상태
- 메뉴별 식재료 원가와 원가 변화
- 예상 재고 및 발주 검토 항목
- 데이터 입력/매핑 완성도

**필터**
- 기간, 메뉴, 카테고리
- POS/파일 수집 방식과 데이터 출처(관리용)

**규칙**
- 실제 데이터가 없으면 허구의 수치 대신 빈 상태 안내를 보여준다.
- CSV 업로드 방식은 파일에 포함된 마지막 시각까지만 집계한다.
- 예측 모델이 없는 초기 버전에서는 “예측” 대신 “기준 재고 알림/계산 결과”로 표시한다.

### S07. 환경설정·매장 정보

**영역**
- 매장 기본정보와 영업시간
- 테이블 및 좌석 배치 수정
- POS 연결 방식 및 연결 상태
- 기본 단위·재고 알림 기준
- 데이터 내보내기 및 백업
- 계정/권한(후속 범위)

**규칙**
- POS 수집 모드를 변경할 때 영향 범위와 중복 수집 방지 절차를 안내한다.
- 과거 기록을 삭제하지 않고, 변경 사항은 이력을 남긴다.

## 6. 공통 이벤트 및 이동 규칙 초안

- 매장 생성 완료 → S01 데이터 수집 방식 설정
- POS 설정 저장 → HOME
- HOME의 메뉴 관리 → S03
- HOME의 식자재/재고 빠른 메뉴 → S05
- S03의 메뉴 상세에서 레시피 수정 → S04의 공통 레시피 편집 컴포넌트 재사용
- S04에서 식자재 연결 메뉴 수정 → 동일한 레시피 관계 갱신
- 결제 완료는 퇴점과 동일하게 취급하지 않는다.
- 테이블 비우기는 이용 세션을 종료하고 기록은 보존한다.
- 저장되지 않은 변경 사항이 있을 때 화면 이동 전 확인한다.

## 7. 미확정 사항 — 인터뷰로 결정

1. 현장에서는 테이블을 착석 시 기록할지, 주문 발생 후 기록할지, 아니면 방문 인원 기록을 선택 기능으로 둘지
2. HOME에서 테이블별 정보와 시간대별 판매량 중 무엇을 가장 먼저 보여줄지
3. 연령대 기록의 필수 여부와 구간 정의
4. 대상 매장이 어떤 POS를 사용할 예정인지 및 실제 API/SDK 사용 권한
5. CSV/Excel 업로드 파일의 열 형식과 업데이트 빈도
6. 폐기 데이터의 1차 범위(일별 총량/메뉴별/테이블별)와 도입 시점
7. 초기 버전에서 재고를 매일 실사할지, 핵심 식자재만 실사할지
8. 데이터 보관·내보내기·백업 정책
