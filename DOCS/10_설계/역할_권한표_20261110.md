# 역할·권한 표 — 2026-11-10

> 2026-11-10 갱신 (U-41): 인증 설계 [[인증_설계_20261110]] 승인. D-A7 확정 — food를 LCI와 다른 호스트로 분리한다(전환은 사용자가 한다). 분리 전까지는 LCI 앱의 XSS가 food 세션에 닿을 수 있다(인증 설계 §11). D-A5, D-R1, D-R2, D-R5는 보류.

상태: **확정 (2026-11-10, U-40).** D-1~D-6은 제안대로 승인됐고 표에 반영했다.

## 1. 근거
- 엔드포인트 목록은 `backend/tests/api/snapshots/openapi.json`(브랜치 `08798b7`)에서 뽑았다: **53개**. FastAPI가 자동으로 만드는 문서 경로 4개를 더해 **57개**다.
- "지금" 열은 전부 같다: **누구나**(로그인 없음, U-14). 그래서 열을 따로 두지 않았다.

## 4. 결정 (2026-11-10 확정, U-40)
| ID | 질문 | 결정 | 이유·조건 |
|---|---|---|---|
| D-1 | 직원의 범위 | **출퇴근만.** 지금 있는 57개 경로는 직원에게 전부 `X` | 요구사항이 "출퇴근 인증이 목적"이다. 권한이 좁을수록 기기 토큰이 탈취됐을 때 피해가 작다. 홀 화면이 필요해지면 #42, #47~50을 따로 결정해 연다 |
| D-2 | 매장 생성 주체 | **운영자만 만들고 점주에게 초대를 준다** | "우리가 만들어서 제공"과 맞는다. 아무 카카오 계정이나 매장을 만드는 일을 막는다 (S-5, O-6) |
| D-3 | 점주와 매장의 관계 | **표는 다대다(`store_members`), 화면은 점주 1 : 매장 1로 시작** | 나중에 구조를 바꾸면 마이그레이션이 필요하다 |
| D-4 | `seed-western-demo` | **운영 환경에서 라우트를 등록하지 않는다** | 로컬·데모에서는 쓰인다 |
| D-5 | 공휴일 수동 추가 | **운영자 전용** | 표가 전역이다. 매장별 휴무일은 다른 기능이다 |
| D-6 | 운영자 역할의 구현 | **초기에는 `backend/scripts/` 방식.** 앱 안에 운영자 역할과 운영자용 HTTP 경로를 두지 않는다. #7, #12 라우트는 제거한다 | 운영자용 HTTP 경로가 없으면 그쪽 공격 면도 없다. **매장이 늘어 수동 운영이 부담되면 운영자 콘솔을 별도 앱으로 만든다**(점주 앱에 운영자 역할을 섞지 않는다). 그때 별도 인증·별도 배포·별도 권한표를 새로 설계한다 |

### 4.1 D-6에서 스크립트가 맡는 일
매장 생성, 점주 초대 발급·폐기, 공휴일 적재(`backend/scripts/fetch_holidays.py`, 이미 있음), 데모 데이터 적재. 스크립트는 소유자 계정이 아니라 **전용 운영 절차**로 실행한다. 실행 계정과 감사 기록 방식은 [[인증_설계_20261110]] §9에서 정한다.

## 5. 아직 없는 엔드포인트 (인증 설계에서 확정)
권한표에 반드시 들어가야 하지만 아직 코드가 없다. 경로는 인증 설계 문서에서 정한다.
- 점주 로그인 시작, 카카오 콜백, 로그아웃, 내 정보·내 매장 목록.
- 매장 초대 수락.
- 직원 기기 등록 요청, 점주의 승인·폐기, 등록 기기 목록.
- 출근·퇴근 기록, 기록 조회, 점주의 정정(이력 보존).
- 손님 등록(카카오): 이번 범위 아님(12월 초 이후).

## 6. 빠짐 방지 (⑦에서 구현)
- 모든 라우트는 역할 의존성 하나를 반드시 선언한다. 선언하지 않은 라우트는 기본 거부다.
- 테스트가 `app.routes`를 전부 돌면서 (1) 이 표에 있는지, (2) 로그인 없이 호출하면 `공개` 경로가 아닌 한 401인지 확인한다. 새 엔드포인트를 표 없이 추가하면 CI가 실패한다 (AC-7).
- 역할별 접근 거부, 다른 매장 거부, 만료 세션 거부, CSRF 거부 테스트를 같은 묶음에 넣는다 (AC-6).
