## 화면 쪽 원인 (코드 확인)

- 홈 `frontend/src/pages/HomePage.tsx`
  - `busy` 하나가 방문 수정·자리·자리 추가·자리 삭제 저장 중 모든 버튼을 잠금. 그래서 +/− 연타가 안 됨.
  - 저장 성공마다 `refreshAll()`이 6개 쿼리(tables, visit-summary, integration-status, sales-orders, inventory-summary, sales-analytics)를 다시 부름.
- **조치:** 착석·인원·자리·배치 변경 6곳은 `refreshFloor()`(tables, visit-summary 2개)만 다시 부르게 바꿈. 주문 수정, 수동 주문, CSV 전환, 배치 초기화는 매출·재고가 바뀌므로 `refreshAll()` 유지.

## 남은 일 (권장 순서)

1. 홈 +/− 낙관적 반영: 누르면 바로 숫자가 바뀌고, 0.3초 동안 연타를 모아 마지막 값만 저장. 실패하면 되돌리고 알림. `busy` 잠금은 되돌리기 어려운 동작(배치 초기화 등)에만 둠.
2. 안전재고 슬라이더 저장 겹침: 최신 값을 ref로 읽고 요청 순번으로 늦게 온 응답을 무시.
3. 재고 요약·판매 분석·식자재: 마지막 실사 이후 기록만 읽기, 또는 일별 집계 테이블. 계산은 결정론적 코드 유지.
4. 손익 65쿼리: 달별 결과 캐시를 한 요청 안에서 공유하거나 월별 묶음 쿼리.
5. 모든 쓰기에 요청 ID(중복 저장 방지). 지금은 근태만 있음.
6. 규약 후보: 저장 1회당 다시 부르는 쿼리 수 상한, 6개월 목데이터로 응답 시간 확인.
