# 계산 규칙 admin 화면 설계 (2026-11-19)

> 근거: U-65, U-67(결정사항_로그). 상태: 설계 확정, 구현 전.

## 1. 목표

사용자가 바꿀 수 없는 계산 규칙을 코드 수정 없이 서비스 admin 계정 화면에서 한 표로 보고 바꾼다.

## 2. 확정 사항 (사용자 인터뷰 2026-11-19)

| 항목 | 결정 |
|---|---|
| 방식 | 규칙 표. 각 규칙은 정해진 선택지 또는 숫자만 바꾼다. 자유 수식은 넣지 않는다(이미 있는 데이터로만 계산하고, 새 로직이 필요한 수식은 받지 않음) |
| 범위 | 전체 매장 공통 한 벌. 매장별 규칙은 나중에 |
| 적용 | 바꾸면 과거 숫자도 새 규칙으로 다시 계산한다. 지금 계산이 전부 조회 시점 계산이라 저장값 재계산 작업은 필요 없다 |
| 접근 | admin 역할은 점주 소셜 로그인(U-66)과 같이 만든다. 그 전에는 규칙 변경 API를 열지 않는다 |
| 제외 | 사용자가 직접 입력하는 값(카드 수수료 %, 안전재고, 판매가, 목표액 등). 카드 수수료는 수식이 아니라 매장 입력 인자다 |

## 3-1. 파생 지표 공식 (현재 구현 — 사용자 검토 대기)

> 사용자 요청(2026-11-19): 마진·이익은 고정비·공과금까지 빼야 한다. 구현과 다르면 사용자가 확인 후 고친다.
> 아래 '현재 구현'은 코드 기준이며, 차감 항목 구성은 admin 규칙 표에서 확인·변경 대상이다.

| 지표 | 현재 구현 | 빼는 항목 | 변경 후보(규칙 옵션) |
|---|---|---|---|
| 메뉴 마진(개당) | 판매가 − 레시피 원가 | 식재료만 | 고정비 배분 차감: 배분 기준 = 매출 비중 / 판매 수량 / 배분 안 함 |
| 메뉴 공헌이익 | 마진 × 판매 수량, 기간 = 전체 | 식재료만 | 기간 = 전체 / 이번 달 / 최근 N일 |
| 영업이익(손익) | 매출 − (식자재 입고액 + 카드 수수료 + 수동 비용 전 항목) | 임대료·인건비·4대보험·전기·수도·가스·배달·포장·광고·부가세 등 손익표 전 항목 | 항목별 포함/제외 체크, 식재료비 = 입고액 / 판매 원가(COGS) |
| 객단가 | 매출 ÷ 주문 수 | — | 분모 = 주문 수 / 손님 수(착석 기록) |
| 재고 평가금액 | 추정 재고 × 단가 | — | 단가 = `cost.unit_price_basis` 따름 |

- 수동 비용 항목 목록: `backend/app/services/pnl.py` 비용 코드(rent, liquor, ingredients, building, labor, social_insurance, delivery_app_fee, delivery_cost, packaging, electricity, water, gas, water_purifier, security, internet, phone, pos, bookkeeping, advertising, vat, other).
- 메뉴 단위로 고정비를 빼려면 배분 기준이 필요하다. 배분은 추정값이므로 화면에 '배분 기준'을 함께 표시한다.
- 미확인: 메뉴 마진의 부가세 포함 여부.

### 3-2. 사용자 결정 (U-68, 2026-11-19)

- 공헌이익 기간: 기본 전체.
- 객단가 분모: 기본 손님 수, 규칙 `kpi.aov_denominator` = guests / orders.
- 영업이익 식재료비: 기본 그 달 입고액, 규칙 `pnl.ingredient_cost_basis` = receipts / cogs.
- 메뉴 마진 고정비 배분: 보류 — 창업·회계 기준 공식 확인 후 결정.
- 손익 비용 항목: admin이 항목을 추가하면 점주 손익 입력 화면에 입력란이 생긴다. 규칙 `pnl.expense_items`(코드·이름·순서·사용 여부).
- 은행 API 대조: 출시·사업자등록 후.

## 4. 구조

- 테이블 `calc_rules(key PK, value JSONB, updated_at, updated_by)` + 변경 이력 `calc_rule_changes(key, old, new, changed_at, changed_by, reason)`. 매장 무관 전역 테이블(RLS 대상 아님).
- 코드에 키별 기본값·허용 범위·선택지를 둔다. DB 값이 없거나 범위 밖이면 기본값을 쓴다. 계산은 기존 서비스 코드가 하고, 규칙 값만 인자로 받는다.
- 프론트 계산 규칙(`kpi.amount_delta_ratio`)은 API로 받아 쓴다.
- 조회 `GET /api/v1/calc-rules`(읽기 전용). 변경 `PUT /api/v1/admin/calc-rules/{key}`는 admin 로그인 이후에만 연다. 변경 사유 필수, 이력 남김.
- 바꾸기 전 미리보기: 샘플 매장 기준 주요 숫자(원가율·손익) 변경 전/후를 보여준다.

## 5. 순서

1. 규칙 테이블 + 기본값 + 조회 API + 서비스가 규칙 값을 읽도록 변경 (현재 값과 같은 기본값이라 화면 숫자 변화 없음).
2. 점주 소셜 로그인 + admin 역할 (U-66).
3. admin 규칙 표 화면 + 변경 API + 이력 + 미리보기.
