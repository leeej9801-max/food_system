# 메뉴 관리 표 밀도 개선

사용자 구현 지시(2026-11-15)를 작업 기준으로 한다. 기존 유형 카드와 보기 버튼 명세보다 이번 지시를 우선한다.

- 범위: 메뉴 관리 화면과 전용 CSS, 필요한 회귀 테스트. 백엔드·API·의존성·홀 화면 변경 제외.
- 요약 카드를 전체 유형 필터로 통합하고 유형은 44px 한 줄 가로 스크롤 탭으로 배치한다. 유형 추가도 같은 줄에 둔다.
- 넓은 화면에서는 앱 뷰포트·헤더 변수로 페이지 높이를 제한한다. 표는 남은 공간을 채우고 내부만 스크롤하며 헤더를 고정한다. 좁은 화면은 문서 스크롤을 허용한다.
- 클라이언트에서 20행 단위로 페이지를 나눈다. 검색·유형·상태가 바뀌면 첫 페이지, 삭제 등으로 줄어들면 마지막 유효 페이지로 보정한다.
- 모든 열은 왼쪽 정렬. 검색과 상태 필터를 왼쪽에 모으고 메뉴 추가는 표 툴바 오른쪽으로 이동한다.
- 운영 토글은 즉시 반응하고 실패 시 복구·오류 알림. 180ms 이동, 동작 줄이기 설정에서는 이동 없음.
- 레시피 상태 칩은 메뉴명과 상태를 포함한 접근 가능한 버튼이며 기존 모달을 연다.
- 검증: 페이지 경계·필터·기존 동작 회귀 확인, tsc/eslint/vitest/vite build. 실기기·브라우저 미실행 시 미검증으로 보고한다.
- 예상 변경: MenuManagementPage.tsx, index.css, 메뉴 관리 테스트. 모달은 필요할 때만 변경한다.
- 완료: 네 검사 성공, self-review·IR·인수인계 기록, 1~3개 한국어 커밋. push·merge 금지.
