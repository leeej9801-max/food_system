# WO-20261104-001 — 매장 간 데이터 격리(B안) 스파이크 + 손님 영역 설계 문서

| ID | 상태 | 작성일 | 관련 문서 | 관련 작업 | 관련 결정 |

## 1. 목적 / 문제

사용자 인터뷰(2026-11-04)로 제품에 **영역 B(손님 유치·홍보: 테이블 QR 캐릭터 + 매장 TV 도트 홀)**를 추가하고, 캐릭터·손님 ID를 **전역 ID**로 두기로 했다. 매장 간 데이터 격리 방식을 성능·보안·비용 기준으로 비교한 결과 **B안(앱 계층 `store_id` 강제 + PostgreSQL RLS 안전망)**이 후보이며, 사용자는 "테스트로 확인"을 요청했다. 또한 베타(양식당 1곳)는 로그인 없이 진행하되 나중에 인증을 크게 고치지 않고 붙일 수 있는 구조가 필요하다.

## 2. 범위

### 포함
- 인터뷰 결정 기록: [[결정사항_로그]] U-16~U-22, [[인터뷰_기록]] 8회차.
- ADR: 매장 격리 B안, 요청 컨텍스트(인증 준비 구조) — [[ADR-013_매장격리_B안_앱계층_RLS]].
- 손님 영역 설계 초안: 흐름 정의(세션·슬롯 상태, 시점별 케이스) + ERD 초안 — [[손님영역_흐름정의_및_ERD_초안]].
- 개인정보 처리 설계 초안(법적 역할 가설, 동의 구조) — [[개인정보_처리설계_초안]].
- B안 스파이크 코드:
  - `backend/app/db/tenancy.py`: 요청 컨텍스트와 트랜잭션 단위 매장 범위 설정 helper.
  - `backend/tests/isolation/`: PostgreSQL 전용 RLS 격리 테스트(환경변수 없으면 skip).
  - `backend/scripts/rls_benchmark.py`: RLS 유/무 동일 쿼리 성능 비교.

### 제외 (비범위)
- 기존 API·서비스·Alembic 마이그레이션에 RLS 적용 (후속 WO). 스파이크는 별도 스키마에서만 검증한다.
- 손님 QR 화면·캐릭터·매장 TV 화면 구현, 로그인·인증 구현.
- 작업규약 §2(고객 개인정보 미수집) 개정 — 법률 검토 후 별도 결정.

## 3. 관련 결정
- P-05(인증 없음), P-07(테스트 SQLite) — RLS는 PostgreSQL 기능이라 격리 테스트만 PostgreSQL에서 실행한다.

## 4. 선행 조건
- Docker Desktop(로컬), `postgres:17-alpine` 일회용 컨테이너(포트 `127.0.0.1:55432`, 테스트 전용 비밀번호는 문서·코드에 기록하지 않음).

## 5. 구현 요구사항
1. RLS 정책은 fail-closed: 매장 범위가 설정되지 않으면 매장 테이블은 0행.
2. 앱 런타임 DB 계정은 테이블 소유자·슈퍼유저가 아니며 `BYPASSRLS` 없음. 매장 테이블은 `FORCE ROW LEVEL SECURITY`.
3. 매장 범위는 트랜잭션 단위(`set_config(..., true)` = `SET LOCAL`)로만 설정해 커넥션 풀에서 새지 않게 한다.
4. 전역 테이블(손님 프로필·캐릭터)은 RLS 대상이 아니며 매장 범위 없이 조회 가능.

## 6. 수용 기준 (검증 가능)
- [ ] AC-1 격리 테스트: 자기 매장만 조회, 범위 미설정 0행, 타 매장 INSERT 거부, 타 매장 UPDATE/DELETE 0행, 앱 필터를 빼도 격리, 풀 커넥션 재사용 시 범위 누수 없음, 전역 테이블 조회 가능 — 모두 통과.
- [ ] AC-2 런타임 계정 권한 점검 테스트(슈퍼유저 아님, BYPASSRLS 없음, 소유자 아님) 통과.
- [ ] AC-3 벤치마크: 대표 쿼리 RLS 유/무 실행 시간 측정값을 TEST 문서에 기록.
- [ ] AC-4 기존 백엔드 테스트(SQLite) 회귀 없음, `ruff check` 통과.
- [ ] AC-5 결정·ADR·설계·개인정보 문서 작성, 링크 연결.

## 7. 테스트 계획
- `RLS_TEST_DATABASE_URL`(소유자 계정 URL)을 설정하고 `pytest tests/isolation -v`.
- 환경변수 없이 `pytest` 전체 실행 시 격리 테스트는 skip, 기존 테스트는 통과.

## 8. 위험 / 미결정 / PROVISIONAL
- 벤치마크는 로컬 Docker 단일 실행 수치라 운영 환경 성능을 보장하지 않는다.
- 법적 역할 표는 가설이며 법률 자문이 아니다.
