# WO-20261111-002 — 손익계산서와 분석 화면

| ID | 상태 | 작성일 | 관련 문서 | 관련 작업 | 관련 결정 |

## 1. 목적 / 문제
지금 분석 화면은 임시 분석이다. 사장님이 실제로 보는 것은 엑셀 "약식 손익계산"이다(총매출, 총지출, 영업이익률, 항목별 금액과 매출 대비 비율). 이 표를 서비스 안에서 월별로 만들고, 값은 가능한 한 이미 있는 데이터에서 자동으로 채운다.

## 2. 범위
### 포함
1. **월별 손익표 (매장·연월 단위).** 항목과 값의 출처:

| 항목 (엑셀 기준) | 출처 |
|---|---|
| 총매출 | 자동: 그 달 판매 주문 합계(POS·CSV 수집 데이터) |
| 식자재 사입비 | 자동: 그 달 입고(`inventory_receipts.total_cost`) 합계. 수기로 덮어쓸 수 있다 |
| 카드수수료 | 자동: 총매출 × 수수료율(기본 2%, 매장 설정), 그 달 값을 수기로 덮어쓸 수 있다(사용자 확인 2026-11-11). **PROVISIONAL**: 전부 카드 결제로 가정 |
| 임대료(부가세 포함), 주류 사입비, 건물관리비, 직원인건비, 4대보험비, 배민·요기요·쿠팡 수수료, 지출된 배달비용, 포장비용 일체, 전기세, 수도세, 가스비, 정수기, CCTV·캡스, 인터넷, 전화비, 포스기, 세무기장료, 광고비, 부가세, 화재보험 | 수기: 월별 입력. 고정비는 "지난달 값 복사" 버튼 |
| 기타 | 수기: 사장님이 이름을 붙여 추가 |

   - 계산: 총지출 = 항목 합계, 영업이익 = 총매출 − 총지출, 각 비율 = 금액 ÷ 총매출. 결정론적 코드로 계산한다(LLM 없음).
2. **DB.** `monthly_expenses`(store_id, 연월, 항목 코드, 금액, 수기 여부) — 매장 범위 RLS 적용. 항목 목록은 코드 상수.
3. **API.** `GET /stores/{id}/pnl?month=YYYY-MM`(표 전체), `PUT /stores/{id}/pnl/{month}/expenses`(수기 항목 저장).
4. **화면.** 새 메뉴 `손익`(`/food/pnl`)을 만든다. 기존 분석 화면은 그대로 둔다(사용자 확인 2026-11-11). 엑셀과 같은 순서의 표 + 위쪽에 총매출·총지출·영업이익률 카드 + 최근 6개월 영업이익 추이.
5. 테스트: 계산(0원 매출, 음수 이익, 반올림), 월 경계(Asia/Seoul), 매장 격리.

### 제외
- 근태 기반 인건비 자동 계산(근태 WO 뒤), 배달앱 정산 연동, 세무 신고용 장부.

## 3. 미결정
- 카드 결제 비율을 따로 받을지(현금·이체 매출 분리). 지금은 전부 카드로 가정.
- 부가세를 수기로 둘지, 매출 기준 추정치를 보여 줄지. 지금은 수기.

## 4. 수용 기준
- AC-1 엑셀 예시 값(총매출 38,000,000 등)을 넣으면 총지출 31,311,800, 영업이익 6,688,200, 영업이익률 17.6%가 나온다(카드수수료 900,000은 예시 값을 수기로 넣어 맞춘다).
- AC-2 판매·입고 데이터가 있는 달은 총매출·식자재 사입비가 자동으로 채워진다.
- AC-3 다른 매장 데이터가 섞이지 않는다(RLS 테스트).
- AC-4 CI 초록불, 브라우저 확인.

## 5. 결과 (2026-11-11)
- 백엔드: `stores.card_fee_percent`(기본 2.00) 추가, `monthly_expenses` 표(매장 RLS) — 마이그레이션 `0009_monthly_pnl`. 서비스 `app/services/pnl.py`, 엔드포인트 `GET /stores/{id}/pnl?month=`, `PUT /stores/{id}/pnl/{month}/expenses`. 수기 값이 있으면 자동 값을 덮어쓴다. 월 경계는 매장 시간대 기준. 금액은 원 단위 반올림, 비율은 소수 1자리.
- 화면: 새 메뉴 `손익`(`/food/pnl`). 월 선택, 카드 3개, 엑셀 순서 표(자동 항목 표시), "지출 입력" 편집, 기타 항목 추가, 카드수수료율, "지난달 값 복사", 최근 6개월 막대.
- 테스트: `tests/api/test_pnl_api.py` 5개(AC-1 엑셀 값, 자동 항목·KST 월 경계, 0원 매출·적자, 입력 검증, 매장 격리). 백엔드 전체 108 통과, 프론트 35 통과, lint·typecheck 통과.
- 브라우저(로컬, 데스크톱): 저장 → 임대료 5,100,000 + 전기세 700,000 반영. 판매 320,000 입력 → 카드수수료 6,400(2.0%) 자동, 입고 224,000 자동.
- 미검증: "지난달 값 복사" 버튼 브라우저 클릭, 모바일 폭.
- 발견(이 WO 범위 밖): CSV 수집은 시간대 없는 시각을 UTC로 읽는다(`app/services/imports.py:86,92`). 한국 POS 내보내기면 9시간 밀려 월말 자정 근처 주문이 다른 달로 갈 수 있다. 별도 수정 필요.
