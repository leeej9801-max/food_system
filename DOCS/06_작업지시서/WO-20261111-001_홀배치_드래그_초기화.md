# WO-20261111-001 — 홀 배치: 드래그 이동과 배치 초기화

## 1. 목적 / 문제
- 지금은 편집 모드에서 테이블을 누른 뒤 바닥을 눌러 옮긴다(`frontend/src/components/FloorPlan.tsx:84-98`). 어디로 갈지 미리 보이지 않아 알아보기 어렵다(사용자, 2026-11-11).
- 배치를 처음 상태로 되돌릴 방법이 화면에 없다. 도면 프리셋(`meal_love`)은 서버 명령(`scripts.apply_floor_preset`)으로만 적용된다.

## 2. 범위
### 포함
1. **드래그 이동.** 편집 모드에서 테이블을 끌어 옮긴다. Pointer Events로 마우스와 터치를 같이 처리한다.
   - 끄는 동안 테이블이 칸에 맞춰 따라오고, 놓을 때 한 번만 저장한다(`PATCH .../tables/{id}`의 `grid_x`, `grid_y`).
   - 바닥 범위 밖으로는 나가지 않는다(기존 계산 그대로).
   - 다른 테이블·고정물과 겹치는 자리는 빨간색으로 표시하고, 놓으면 원래 자리로 돌아간다(사용자 확인 2026-11-11).
   - 누르고 바닥을 누르는 기존 방식은 없앤다.
2. **배치 초기화.** 홈 화면 "배치 편집" 도구줄에 버튼을 둔다(편집 중에만 보인다). 누르면 확인 창을 띄운 뒤 서버에 요청한다.
   - API: `POST /api/v1/stores/{store_id}/floor/reset`. 기존 `apply_floor_preset(..., "meal_love")`를 재사용해 도면 배치로 되돌린다(사용자 확인 2026-11-11). 기본 격자 초기화는 넣지 않는다.
   - 감사 로그를 남긴다(기존 `floor_preset` 기록 방식).
3. 테스트: 초기화 API(멱등, 매장 격리 404), 프론트 겹침 판정(`canPlace`) 단위 테스트 1개.

### 제외
- 테이블 크기·방향을 드래그로 바꾸기, 고정물 이동, 실행 취소.

## 3. 수용 기준
- AC-1 마우스와 터치 모두에서 끌어서 옮기고, 새로고침해도 위치가 유지된다.
- AC-2 초기화 버튼을 누르면 확인 뒤 배치가 정해진 상태로 돌아가고, 두 번 눌러도 결과가 같다.
- AC-3 다른 매장 ID로 초기화를 부르면 404.
- AC-4 CI 초록불, 브라우저(데스크톱 + 모바일 폭)에서 확인.

## 4. 결과 (2026-11-11)
- 백엔드: `backend/app/api/v1/endpoints/tables.py` `reset_floor`, 테스트 `test_floor_reset_api_restores_preset`.
- 프론트: `frontend/src/components/FloorPlan.tsx` 드래그(Pointer Events, 놓을 때 한 번 저장, 겹치면 빨간색 + 원래 자리), `canPlace` 테스트 `FloorPlan.test.ts`. 홈 편집 도구줄에 "배치 초기화".
- 브라우저 확인(로컬, 데스크톱 폭, 마우스): T2와 겹치게 끌면 빨간색 → 놓으면 원래 자리, 빈 곳에 놓으면 PATCH 1번 + 새로고침 뒤 유지, 초기화 누르면 (1,3)으로 복귀 + 안내 문구.
- **미검증:** 터치(실제 폰), 모바일 폭 화면.
