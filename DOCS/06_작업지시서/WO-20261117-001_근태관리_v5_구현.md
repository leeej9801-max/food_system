# WO-20261117-001 — 근태 관리 v5 구현

## 1. 목적 / 문제
승인된 `design/mockups/attendance/mockup_attendance_v5.html`을 실제 매장 데이터와 연결한 근태 관리 화면으로 구현한다. 작업 위치는 `feature/attendance` worktree만 사용한다.

## 2. 범위
직원 이름·역할·색 등록/목록, 일·주·월 스케줄, 점주 근무, 날짜 달력, 편집 가능한 시간 프리셋과 휠, 출퇴근 원본·정정 이력, 누락·실제 시간·공백 집계, 동기 3계층 API와 Alembic 마이그레이션을 포함한다.
시급·인건비, QR, 소셜 로그인, 기기 등록, 실제 점주 비밀번호 인증, 배포·커밋·push는 제외한다.

## 3. 관련 요구사항·화면·결정
사용자 직접 작업 지시의 항목 1~7, U-24, ADR-014, 인증 설계 §6.4. 기존 S00~S07 번호를 새로 배정하지 않는다.

## 4. 선행 조건
AGENTS, canonical 규약, 인수인계, 인증 설계 §6, 승인 HTML 및 `v5_week_dp.png`, `v5_month.png`, `v5_day.png`, `v4_time.png`를 확인했다. 기존 셸·Dialog·API 검증·매장 범위 패턴을 재사용한다.

## 5. 구현 요구사항
- `/attendance`와 사이드바. CSS는 `frontend/src/styles/attendance.css`, `@layer components`, 화면 루트로 범위를 제한한다.
- 24시간 일간 막대 양끝 30분 단위 조절, 최소 1시간. 주간 월~일 드롭·기간 확장·시간 설정. 월간 날짜 드롭·모달. 키보드로도 동일한 입력이 가능해야 한다.
- 달력 선택·이전·다음·오늘 및 하단 집계가 같은 선택 기간을 사용한다. 휴무일은 매장 설정을 사용한다.
- 원본과 정정은 INSERT/SELECT만 허용한다. 서버 시각·매장 범위·사유 검증·원본 보존을 테스트한다.
- 직접 등록 및 비밀번호 재확인 미구현은 PROVISIONAL로 표시한다.

## 6. 수용 기준
- 직원·스케줄·프리셋·기록이 API에 저장되고 새로 조회해 유지된다.
- 잘못된 시간·직원/매장 혼용·빈 정정 사유를 거부한다.
- 정정 후 원본이 유지되고 마지막 정정과 전체 이력을 볼 수 있다.
- 점주 근무와 휴무는 공백에서 제외한다. 누락 시간은 미산출로 구분한다.
- 지정 검사 실제 결과와 1280px 캡처 시도 결과를 IR에 기록한다.

## 7. 테스트 계획
관련 pytest(SQLite 격리 설정 사용 가능), ruff, tsc, 변경 파일 ESLint, Vitest, 빌드, 브라우저에서 일간/주간/월간/달력/모달 캡처를 시도한다. 실행 실패는 원문과 원인을 기록한다.

## 8. 위험 / 미결정 / PROVISIONAL
로그인 미구현으로 실제 점주 권한·재인증은 제공하지 않는다. 출시 보안 완료로 보고하지 않는다. 법정 보관·휴게·수당 정책을 확정하지 않는다. 다른 브랜치의 미커밋 `0014_monthly_goals`와 병합할 때 Alembic head 분기 가능성을 기록한다.

## 9. 예상 수정 파일
backend models/repositories/services/schemas/endpoints/router, runtime 역할 권한 스크립트, migration, 관련 테스트. frontend App, attendance API/lib/components/page/CSS/tests. WO/IR/REV/인수인계/허브/변경이력.

## 10. 완료 조건
구현 및 실제 검사 결과를 IR에 기록하고 self-review REV와 인수인계를 갱신한다. 금지 파일을 수정하지 않고 커밋·push하지 않는다.
