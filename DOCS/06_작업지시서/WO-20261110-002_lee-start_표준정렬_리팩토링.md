# WO-20261110-002 — lee-start 표준 정렬 리팩토링

|---|---|---|---|---|---|

## 1. 목적
food를 lee-start 표준에 맞춘다. 동작은 바꾸지 않는 정리를 먼저 하고, 동작이 바뀌는 항목은 따로 표시해 사용자 확인을 받는다.

## 2. 단계
| 단계 | 내용 | 상태 |
|---|---|---|
| 준비 | `main` 최신, 브랜치 `refactor/lee-start-alignment`, 기준선 테스트 | 완료 (백엔드 47, 격리 22, 프론트 7 통과) |
| 1 | 감사, 수정 없음 | 완료 → [[lee-start_표준격차_감사_20261110]] |
| 2 | 안전망 테스트 추가(구현 변경 없음): 감사 §5 | 완료 (다른 매장 접근 19개 경로 404, 목록 누출 없음, 오류 형식 3종, OpenAPI 스냅샷. 백엔드 73 통과) |
| 3 | 작은 단위 정리: CI → pyright → ruff 규칙 → 임시 흔적 → 구조 | 진행 예정 (U-36) |
| 4 | 동작이 바뀌는 표준 항목: SEC-001, API-004, TS-010, API-001, DB-001, API-003 | 항목별 사용자 결정 대기 |

2026-11-10 사용자 지시(U-36): 실사용 서비스로 격상, 개발 진행 전에 리팩토링을 모두 끝낸다. 범위를 감사의 전 항목으로 넓힌다.

## 3. 규칙
- 묶음 하나가 끝날 때마다 테스트 통과를 확인하고 커밋한 뒤 보고한다.
- 동작이 바뀌는 변경(감사 §6의 결정 항목)은 사용자 확인 없이 하지 않는다.
- async 전환은 제외한다. 별도 결정으로 남긴다.
- 라이브 `/food` 재배포는 사용자 확인 후에만 한다.
- `backend/requirements.deploy.txt`는 배포 필수 파일이므로 지우지 않는다.

## 4. 수용 기준
- [ ] AC-1 각 묶음 뒤 백엔드 pytest, PostgreSQL 격리 테스트, 프론트 typecheck·test·build 통과.
- [ ] AC-2 2단계 테스트는 구현을 바꾸지 않고 현재 동작에서 통과.
- [ ] AC-3 CI가 격리 테스트를 skip 없이 실행.
- [ ] AC-4 정리 전후 OpenAPI 스키마 동일(의도한 변경 제외).
- [ ] AC-5 실행하지 않은 검증은 IR에 `미검증`으로 표시.

감사 §6 "사용자 결정 필요" 항목: SEC-001, API-004, DB-001, API-001, API-003, TS-010.
