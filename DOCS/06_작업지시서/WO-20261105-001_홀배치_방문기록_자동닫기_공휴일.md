# WO-20261105-001 — 홀 배치·방문 기록·자동 닫기·공휴일

## 1. 목적 / 문제
매장 A(meal love) 사장님 요구 2·3번을 위한 **입력 기반**을 만든다 (사용자 지시: "05~07부터 하자", [[인터뷰_기록#10회차]]).
- 홀 화면이 3×4 격자라 실제 매장 배치와 다르다. 도면대로(바른 방향, 테이블 가로/세로 방향) 보여야 한다.
- 객층(성별·연령), 방문 목적, 동반 관계를 받을 곳이 없다(연령은 직원이 대표값 하나만 입력).
- 퇴점을 누르지 않으면 세션이 계속 열려 회전수가 틀어진다.
- 평일/주말 구분에 공휴일 자료가 없다.
- 기록 화면이 스크롤되어 일하면서 쓰기 어렵다.

분석 화면(객층·시간대별 회전수·목적, 평일/주말)은 후속 대시보드 WO에서 이 데이터를 읽어 만든다.

## 2. 범위
### 포함
1. **테이블 배치 좌표 확장 + 방향**
   - `store_tables.orientation`(`H` 가로 / `V` 세로)을 추가한다.
   - 좌표 범위를 `grid_x 0..23`, `grid_y 0..27`로 넓힌다. 1칸은 약 34cm이고, 1200×600 테이블은 4×2칸이다.
   - 기존 0..11 / 0..7 값은 그대로 유효하다.
2. **매장 도면 고정물**
   - `stores.floor_fixtures`(JSON 텍스트)를 추가한다. 입구·카운터·칸막이·주방 위치를 같은 좌표계로 둔다.
   - 매장 A 도면 프리셋 적용 스크립트를 만든다. 12테이블 4인석 + 고정물이며, 기존 테이블은 이름 기준으로 재사용하고 삭제하지 않는다.
3. **사람별 성별·연령대**
   - `session_slots`에 `gender`(`FEMALE`/`MALE`/`UNRECORDED`), `age_band`(기존 `AgeBandType`), `profile_source`(`GUEST`/`STAFF`/`NULL`)를 추가한다.
   - 손님은 자기 슬롯(가져간 슬롯)에만 입력한다.
   - 직원은 손님이 입력하지 않은 슬롯에만 입력한다. 손님 값 우선(U-18 인원 출처 우선순위와 같은 원칙)이다.
   - 세션 `age_band`는 슬롯에서 다시 계산한다(모두 같으면 그 값, 섞이면 `MIXED`, 없으면 `UNRECORDED`). 기존 분석과의 호환을 위해서다.
4. **세션별 방문 목적·동반 관계**
   - `visit_sessions.purpose`, `visit_sessions.relationship`을 추가한다. 선택지는 PROVISIONAL이며 §8에 적었다.
   - 손님 API와 직원 API 모두에서 입력할 수 있다. 손님이 입력한 값을 직원이 덮어쓰지 않는다.
5. **자동 닫기(`END_OF_DAY`)**
   - 열린 세션이 그 영업일의 종료 시각(`stores.opening_hours` "HH:MM-HH:MM", 매장 시간대)을 지나면 `LEFT`·`closed_reason=END_OF_DAY`로 닫는다. `left_at`은 종료 시각이다.
   - 별도 스케줄러 없이 홀·방문·손님 API를 호출할 때 먼저 정리한다. 이 방식을 "지연 닫기"라고 부른다.
   - 종료 시각을 읽을 수 없으면 닫지 않는다.
6. **공휴일**
   - 전역 `holidays` 테이블(date PK, name, source `KASI`/`MANUAL`)을 만든다. 매장 데이터가 아니므로 RLS를 걸지 않는다(ADR-013 전역 테이블).
   - 천문연 특일정보 수집 스크립트를 만든다(`KASI_SERVICE_KEY`, 연 단위). 인증키가 없으면 오류를 내고 종료한다.
   - 공휴일 조회·수동 추가 API를 만든다.
   - 날짜 구분 헬퍼 `day_type(date) → WEEKDAY/WEEKEND/HOLIDAY`를 만든다.
7. **기록 화면(HOME S02)**
   - 갤럭시탭·아이패드 가로/세로(아래 §6 크기)에서 **문서 스크롤 없이** 홀 배치와 선택 테이블 입력 패널이 한 화면에 보이게 한다.
   - 배치도는 좌표·방향대로 그린다.
   - 입력 패널은 인원, 사람별 성별·연령, 목적, 관계, 결제·퇴점이다.
   - 설정 화면 배치 편집도 새 좌표계로 바꾼다(테이블 선택 → 도면 위 위치 탭, 방향 전환).

### 제외 (비범위)
- 분석·대시보드 화면(후속 WO), 날씨(후속 WO), 목표·직원·손익.
- 로그인·권한(U-25, 매장 제공 전 별도 WO).
- 손님 모바일 화면 UI(API만 추가). 캐릭터, TV 화면.
- 라이브 `/food` 재배포(사용자 확인 후 별도).
- 동반자 입력 주체 최종 결정(1번, 사장님 B안 협의 후).

## 3. 관련 요구사항·화면·결정
- 화면: S02 HOME, 설정(테이블 배치).
- 결정: U-31(이번 범위), U-28(공휴일), U-19(퇴점 우선순위·유예 없음), U-23·P-15(개인정보: 성별·연령대는 익명 집계값이고 이름·연락처는 받지 않음), ADR-013(매장 테이블 RLS, 전역 테이블 무RLS), P-11(기존 연령 입력 대체).

## 4. 선행 조건
- 문서: [[결정사항_로그]] U-24~U-32 기록 완료.
- 환경: `cd backend; uv sync --extra dev`, 격리 테스트용 일회용 PostgreSQL(127.0.0.1:55432).

## 5. 구현 요구사항
- Alembic `0008`: 컬럼 추가는 모두 nullable이거나 server_default를 둔다(기존 행 유지). `holidays`는 전역 테이블이다. 새 매장 테이블은 없다. 기존 `session_slots`·`visit_sessions`·`store_tables`·`stores`의 정책을 그대로 쓴다.
- `downgrade`로 되돌릴 수 있어야 한다.
- 런타임 역할은 `holidays`를 읽기만 하고, 수동 추가 API를 위해 INSERT만 허용한다. `ensure_runtime_role`의 기본 권한으로 충분한지 확인한다.
- 자동 닫기 시각은 UTC로 저장한다(매장 시간대 → UTC 변환).
- 손님 API 추가:
  - `PATCH /api/guest/v1/qr/{token}/session` `{purpose?, relationship?}`
  - `PATCH .../session/slots/{n}`에 `{gender?, age_band?}` 추가(자기 슬롯만, 아니면 403)
- 직원 API 추가:
  - `PATCH /api/v1/stores/{s}/visits/{v}` `{purpose?, relationship?}`
  - `GET/PATCH /api/v1/stores/{s}/visits/{v}/slots[/{n}]` `{gender?, age_band?}` (손님 입력 슬롯이면 409 `SLOT_PROFILE_BY_GUEST`)
- 프론트 크기 기준: 1024×768, 768×1024(아이패드 9~10세대), 1180×820, 820×1180(아이패드 Air), 1366×1024, 1024×1366(아이패드 Pro 12.9), 1138×712, 712×1138(갤럭시탭 S9 CSS 픽셀 추정), 1280×800, 800×1280(갤럭시탭 A 계열 추정).

## 8. 위험 / 미결정 / PROVISIONAL
- **방문 목적 선택지(PROVISIONAL):** 식사 / 데이트 / 모임·약속 / 가족 외식 / 회식 / 기타. 사장님 확인이 필요하다.
- **동반 관계 선택지(PROVISIONAL):** 혼자 / 연인 / 친구 / 가족 / 동료 / 기타. 사장님 확인이 필요하다.
- **성별(U-31 신규):** 익명 선택값이지만 기기 쿠키와 함께 저장된다. P-15 법률 검토 범위에 더한다.
- **지연 닫기:** 아무도 화면을 열지 않으면 DB에는 열린 채로 남는다. 분석 쿼리도 먼저 정리를 호출해야 한다.
- **영업 종료 시각:** 자정을 넘는 영업("11:00-02:00")은 다음 날 종료로 계산한다. 휴무일은 고려하지 않는다.
- **도면 좌표:** 34cm 칸으로 반올림해서 실제와 최대 약 17cm 차이가 난다.
- **실기기 미검증:** 갤럭시탭 CSS 픽셀은 추정값이다.
- **U-15 노트북 67% 밀도 규칙:** 태블릿은 터치(`pointer: coarse`)라 영향이 없어야 한다. 확인한다.
