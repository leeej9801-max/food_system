## 1. 목적 / 문제

사용자 요청에 따라 MVP P0(`WO-20261025-001` ~ `WO-20261025-006`) 전체 코드베이스를 전수 점검하여:
1. **기획 의도 위배 여부** (1~2인 음식점 데이터 입력 부담 최소화, POS 대체/범용 챗봇 변질 금지, 미검증 기능 완료 위장 금지, 결정론적 계산 원칙, 가짜 기본 매출 표시 금지)를 감사한다.
2. **데이터 수집·정규화·원가·재고 파이프라인의 엣지케이스 및 정합성 결함**을 찾아 수정한다.
3. **백엔드 DB 쿼리(N+1 제거, 선형 인덱싱) 및 프론트엔드 렌더링/UX(React key, 식자재별 개별 단가 시뮬레이션, POS 연결 상태 실시간 반영)**를 최적화한다.

## 2. 감사에서 발견된 개선 대상 (7대 최적화 항목)

1. **[파이프라인 정합성 1 — 업로드/등록 순서 독립성 보장]:**
   - *현상:* CSV 판매 데이터를 **먼저** 업로드(`UNMAPPED`)하고 **나중에** 메뉴 관리(`S03`)에서 동일한 이름의 메뉴를 생성·수정·활성화할 경우, 기존 `UNMAPPED` 판매 항목이 자동으로 해당 메뉴에 소급 연결되지 않았음.
   - *개선:* `create_menu` 및 `update_menu`(활성 상태) 시점에 동일 매장의 `UNMAPPED` `SalesOrderItem`(대소문자·공백 정규화 일치)을 즉시 `MAPPED`로 소급 연결하여 **CSV 업로드 ↔ 메뉴 등록 순서와 무관하게 파이프라인이 100% 일관되게 작동**하도록 개선.
2. **[파이프라인 정합성 2 — Excel UTF-8-BOM(`\ufeff`) 및 대소문자 정규화]:**
   - *현상:* 현장 매장에서 Excel로 저장한 `CSV UTF-8(BOM 포함)` 파일 업로드 시 첫 헤더 컬럼 앞에 `\ufeff`가 붙어 `order_id` 컬럼 인식이 실패할 수 있으며, `_build_menu_lookup`이 대소문자를 구분했음.
   - *개선:* CSV 파싱 시 `\ufeff`(BOM) 제거 및 헤더/셀 공백 정리, 메뉴·상품명 매칭 시 `strip().casefold()` 일관 적용.
3. **[파이프라인 정합성 3 — 실재고 실사(`InventoryCount`) 이후 과거 날짜 CSV 지연 업로드 방어]:**
   - *현상:* 실재고 실사(`baseline_dt`) 이후에 과거 영업일(`ordered_at <= baseline_dt`)의 CSV를 뒤늦게 업로드하면 실사 이후 이론 소모량으로 중복 차감될 수 있었음.
   - *개선:* `received_at > baseline_dt`이면서 동시에 `(ordered_at is None or ordered_at > baseline_dt)`인 판매만 실사 이후 이론 소모량에 반영.
4. **[백엔드 성능 최적화 — N+1 쿼리 제거 및 선형 그룹화]:**
   - `commit_sales_csv`: 주문 건별 개별 `SELECT` 루프를 단일 `IN` 배치 조회로 변경.
   - `upsert_menu_recipe`: 레시피 식자재 검증 시 개별 `SELECT` 루프를 단일 `IN` 배치 조회로 변경.
   - `get_inventory_summary`: 식자재별 중첩 루프(`O(I × (R + C + A + S))`)를 사전 딕셔너리 인덱싱(`O(I + R + C + A + S)`)으로 최적화.
5. **[기획/UI 정합성 — 메뉴 관리(`S03`)의 POS 연결 상태(`pos_mapping_status`) 실제 데이터 연동]:**
   - *현상:* `WO-001` 당시 임시 고정값(`UNLINKED_PROVISIONAL`)이 `S03` 테이블에 계속 표시됨.
   - *개선:* `PosProductMapping` 또는 매칭된 `SalesOrderItem`이 존재하면 `"LINKED"`(`● 연결됨 (POS/CSV)`), 아직 없으면 `"UNLINKED_PROVISIONAL"`(`대기 (이름 자동매칭)`)로 실제 상태를 반영.
6. **[프론트엔드 UX 및 기획 완성도 — 분석 대시보드(`S06`) 식자재별 개별 단가 변동률 시뮬레이터 추가]:**
   - 전체 일괄 변동률(`-5%~+20%`)뿐 아니라, 메뉴의 구성 식자재 아코디언을 열면 **특정 식자재(예: 관찰레만 `+30%`)의 개별 단가 변동률**을 직접 입력해 비파괴 시뮬레이션할 수 있도록 고도화.
7. **[프론트엔드 코드 품질 — React Fragment key 수정]:**
   - `AnalyticsPage.tsx`의 메뉴 테이블 `.map()` 내부 `<>`를 `<Fragment key={m.menu_item_id}>`로 수정하여 React key 경고 원천 제거.

## 3. 수용 기준 (Acceptance Criteria)

- **AC-1 (순서 독립적 소급 매핑):** 메뉴 미등록 상태에서 먼저 CSV를 업로드·커밋(`UNMAPPED`)한 뒤, 나중에 `S03`(또는 `POST /menus`)에서 동일 이름의 메뉴를 생성하면 별도 수동 매핑 없이도 기존 판매 항목이 자동으로 `MAPPED`로 전환되고 재고 이론 소모량·원가·판매 순위에 즉시 반영된다.
- **AC-2 (UTF-8 BOM CSV 및 대소문자 매칭):** `\ufefforder_id,...` 형태의 Excel UTF-8 BOM CSV와 영문 대소문자가 다른 상품명도 오류 없이 파싱·매칭된다.
- **AC-3 (실사 이전 과거 주문 지연 업로드 방어):** 실재고 실사(`counted_at`) 이후에 `ordered_at`이 실사 시각보다 과거인 판매 CSV를 업로드하더라도 실사 이후 예상 재고에서 중복 차감되지 않는다.
- **AC-4 (S03 POS 연결 상태 반영):** 판매 데이터 또는 상품명 매핑이 연결된 메뉴는 `GET /menus` 응답에서 `pos_mapping_status == "LINKED"`를 반환하고, 신규 미연결 메뉴는 `"UNLINKED_PROVISIONAL"`을 반환한다.
- **AC-5 (전체 린트·타입·테스트·빌드·링크 검사 무결성):** 백엔드 `ruff`, `pytest`, 프론트엔드 `typecheck`, `test`, `build`, Vault `check-links.ps1` 모두 0 에러로 통과한다.
