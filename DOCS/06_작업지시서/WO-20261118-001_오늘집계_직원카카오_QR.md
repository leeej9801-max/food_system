# 오늘 집계 · 직원 카카오 로그인 · 회전 QR

사용자 확정 지시 A/B, U-24, ADR-014를 구현한다. 지정 feature-attendance worktree만 사용하며 commit/push/운영 배포를 하지 않는다.

## 수용 기준

- 기존 누적 API를 보존하고 매장 timezone의 오늘 [자정, 다음 자정) 방문 시작/인원 및 COMPLETED 매출을 신규 API로 제공한다. 헤더는 신규 값 사용. 자정·시간대 테스트와 OpenAPI 갱신.
- 30초 HMAC-SHA256 QR, 이전 창 1개 허용, 매장별 secret, QR 자체 DB 미저장. 직원/창 재사용 차단, 서버가 현재 상태로 IN/OUT 결정. 기존 불변 이벤트/UUID 멱등 규칙 재사용.
- 1회용 7일 초대 해시, 카카오 id/닉네임 연결 PENDING → 점주 승인 ACTIVE. 매장당 카카오 계정 한 직원. 비활성/미승인 QR 차단.
- state+PKCE, PyJWT access 15분 HttpOnly, refresh 60일 절대 만료/매번 rotation/해시만 저장/재사용 시 직원 세션 모두 폐기. Origin, Secure(로컬 http 예외), SameSite=Lax, 레이트 리밋. 비밀·토큰·QR·code 로깅 금지.
- 점주 초대/승인/QR와 기존 owner-direct는 공개 데모 PROVISIONAL. 점주 로그인/법률 판단은 범위 밖.
- QR 모달 회전·초 카운트·2~3초 폴링 완료, 직원 폰 390px 독립 라우트, 초대 생성/승인 UI.

## 변경 경계

동기 endpoint/service/repository, 인증 모델·migration 0016, attendance 이벤트 트랜잭션 재사용. App 헤더/독립 라우트, 신규 API·모바일·QR·초대관리 컴포넌트. Antigravity 소유 AttendancePage.tsx/attendance.css/lib/attendance.ts 보호. 마지막에 꼭 필요한 버튼/렌더 최소 연결만 허용하고 IR에 명시한다.

frontend package.json/package-lock.json은 인수인계 커밋 금지 목록이므로 변경하지 않는다. QR은 backend SVG 생성 의존성으로 제공한다. backend PyJWT/httpx/QR 의존성은 manifest/uv.lock에 기록한다. 최신 직원 확정안은 기존 인증 설계의 기기등록 가정에 우선하며 원문은 보존한다.

## 검사 및 완료 조건

ruff, pyright, 관련 pytest+근태 SQLite 전체, 가능한 독립 PostgreSQL. tsc, 변경 ESLint, vitest, vite build. 포트 5175/8002만 사용. 1280 QR·헤더와 390 모바일/완료 PNG 4종. 카카오 HTTP fake 테스트와 실 로그인 수동 절차를 IR에 기록한다. IR → self-review REV → 인수인계/허브/변경이력 갱신. 미실행/실패 명시.

0014_monthly_goals와 attendance migration 번호/분기는 병합 담당자의 후속 작업이며 이번에 해결하지 않는다.
