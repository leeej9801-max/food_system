# WO-20261025-004 — 데이터 수집 방식 설정(A/B/C, S01) 및 CSV 판매 데이터 수집 파이프라인

## 1. 목적 / 문제

사용자 지시 순서(`A → B → C`)의 **C 단계**로서 **POS/데이터 수집 방식 설정(`REQ-003`, 화면 `S01`)**, **CSV 판매 데이터 업로드·열 매핑·검증·중복 방지·확정(`REQ-004`)**, **수집 상태 및 데이터 품질 표시(`REQ-011`)**를 구현한다.
통합기획서 핵심 원칙(§6.1~§6.6, §7.4, §8.1~§8.3)을 준수한다:
- 모드 A(토스 Open API), 모드 B(토스 Plugin SDK)는 실제 자격증명·검수가 없으므로 **`PROVISIONAL_UNVERIFIED` (연동 준비 중 / 미검증)**로 정직하게 표시한다.
- 모드 C(CSV/Excel)는 **“실시간 연동”이라고 표현하지 않으며**, 마지막 업로드 시각(`last_uploaded_at`)과 파일 내 마지막 판매 시각(`latest_sale_time`)을 구분해 표시한다.
- 미리보기(`preview`) 없이 바로 DB를 변경하지 않는다: `preview` 단계에서 행별 오류, 중복 파일(`file_hash`), 미매핑 메뉴를 검출·보고하고, 사용자가 `commit`할 때만 정상 행을 `sales_orders` / `sales_order_items`로 반영한다.
- 메뉴명이 내부 메뉴와 연결되지 않은 행도 버리지 않고 판매 기록을 보존하되 `mapping_status="UNMAPPED"` 및 `data_quality_issues`로 기록하며, 사용자가 메뉴 매핑(`pos_product_mappings`)을 등록하면 자동 연결되도록 한다.
- 취소(`CANCELLED`) 상태 행은 원본은 보존하되 순판매량 합계에서 제외한다.

## 2. 범위

### 포함
- **DB & Alembic 마이그레이션 (`0004_pos_imports_and_sales.py`):**
  - `pos_connections`: `id`, `store_id`, `mode`(`TOSS_OPEN_API`, `TOSS_PLUGIN`, `CSV_UPLOAD`), `status`(`UNVERIFIED`, `READY_CSV`), `last_synced_at`, `latest_data_time`, `config_json`, `updated_at`
  - `pos_product_mappings`: `id`, `store_id`, `external_product_name`, `menu_item_id`, `created_at` (`UniqueConstraint(store_id, external_product_name)`)
  - `import_batches`: `id`, `store_id`, `file_name`, `file_hash`, `status`(`PREVIEWED`, `COMMITTED`, `DUPLICATE_WARN`), `rows_total`, `rows_valid`, `rows_error`, `rows_unmapped`, `latest_sale_time`, `preview_json`, `uploaded_at`, `committed_at`
  - `sales_orders`: `id`, `store_id`, `import_batch_id`(nullable), `source_mode`, `external_order_id`, `ordered_at`(nullable), `time_basis`(`order_time`, `date_only`, `unknown`), `status`(`COMPLETED`, `CANCELLED`), `received_at`
  - `sales_order_items`: `id`, `order_id`, `store_id`, `menu_item_id`(nullable), `raw_product_name`, `quantity`(`Integer`), `unit_price`(`Numeric(12,2)`), `status`(`COMPLETED`, `CANCELLED`), `mapping_status`(`MAPPED`, `UNMAPPED`), `ordered_at`(nullable)
  - `data_quality_issues`: `id`, `store_id`, `batch_id`(nullable), `issue_code`, `message`, `raw_product_name`(nullable), `resolved`(bool), `created_at`
- **백엔드 API (`/api/v1/stores/{store_id}/...`):**
  - `GET /integrations/status`, `PUT /integrations/mode` (모드 A/B/C 전환 — 기존 기록 삭제 안 함, A/B는 `UNVERIFIED` 명시, 최신 수집 시각·미매핑 메뉴 수·오늘 순매출 요약 반환)
  - `GET /imports/sales/sample-csv` (양식당 기준 샘플 판매 CSV 텍스트/구조 제공)
  - `POST /imports/sales/preview` (CSV 문자열 + 열 매핑 설정을 받아 행별 검증, 파일 해시 중복 감지, 미매핑 메뉴 검출 후 `import_batch` `PREVIEWED` 생성)
  - `POST /imports/sales/{batch_id}/commit` (`PREVIEWED` 배치를 확정하여 정상 행을 `sales_orders` / `sales_order_items`로 영속화, 동일 `external_order_id + raw_product_name` 재수집 시 중복 추가 대신 멱등 갱신)
  - `GET /imports/sales` (업로드 배치 이력 조회)
  - `GET/POST /product-mappings` (미매핑 상품명을 내부 메뉴 `menu_item_id`에 매핑하고 기존 `UNMAPPED` 판매 항목도 일괄 연결 갱신)
- **프론트엔드 (`S01`, `S02`, `S07`):**
  - `S07 / S01` 통합 설정 화면에 **데이터 수집 방식 설정(`S01`) 및 CSV 판매 업로드 위저드** 탑재:
    - A/B/C 모드 선택 카드 및 모드별 지원 범위 표 (A/B는 `연동 준비/미검증` 배지)
    - 양식당 샘플 CSV 원클릭 불러오기 또는 로컬 `.csv` 파일 선택
    - 열 매핑 UI (주문번호, 판매일시, 메뉴명, 수량, 단가, 주문상태)
    - `[1단계: 미리보기 및 검증]` → 정상/오류/미매핑/중복 경고 확인 → `[2단계: 가져오기 확정]`
    - 미매핑 상품명을 내부 메뉴와 즉시 연결하는 매핑 패널
  - 상단 헤더 및 `S02 HOME` 매출 카드에 실제 수집된 순매출·마지막 업로드 시각·데이터 기준 시각 연동

## 3. 수용 기준 (검증 가능)
- [ ] AC-1 수집 모드를 A/B/C로 변경할 수 있으며, A/B는 `UNVERIFIED` 상태로 표시되고 모드 변경 시 기존 판매 기록이 삭제되지 않는다.
- [ ] AC-2 정상 CSV 데이터를 `preview` 후 `commit`하면 `sales_orders` 및 `sales_order_items`에 반영되고 순매출·순판매량이 정확히 계산된다.
- [ ] AC-3 취소(`CANCELLED` / `취소`) 행은 원본은 저장되나 순판매량·순매출 집계에서 제외된다.
- [ ] AC-4 잘못된 수량/가격이나 빈 메뉴명이 있는 행은 `preview`에서 행 번호와 함께 오류로 분류되고 `commit` 시 제외된다.
- [ ] AC-5 동일한 CSV를 다시 `preview`/`commit`할 때 중복 파일 경고(`duplicate_file_warning=true`)를 표시하고, `external_order_id` 기준으로 판매 수량이 중복 누적되지 않는다(멱등성).
- [ ] AC-6 내부 메뉴에 없는 상품명은 판매 기록을 버리지 않고 `UNMAPPED`로 보존하며, `POST /product-mappings`로 매핑하면 `MAPPED`로 갱신된다.
- [ ] AC-7 프론트엔드 타입 검사·단위 테스트·프로덕션 빌드가 통과한다.
