# WO-20261025-003 — 매장 초기 설정·테이블 구성(S00/S07) 및 HOME(S02) 방문 세션 기록

## 1. 목적 / 문제

사용자 2차 인터뷰 지시(`U-06`: "B. 도트는 나중에 해도 되니 일단 기능 되게")에 따라 **매장 초기 설정·테이블 구성(`REQ-001`, `REQ-002`, 화면 `S00`·`S07`)**과 **HOME(`S02`)의 테이블 상태·방문 세션(`visit_sessions`) 기록 흐름**을 end-to-end로 구현한다.
통합기획서 핵심 원칙(§1.6, §9.4)을 엄격히 준수한다:
- **결제 완료와 실제 퇴점(테이블 비우기)은 별도 이벤트/상태로 분리**한다 (`SEATED` → 선택적 `PAID` → `LEFT`).
- **테이블을 비워도(`LEFT`) 과거 방문 세션 기록(`visit_sessions`)은 삭제되지 않고 보존**된다.
- POS에서 메뉴/주문을 가져오거나 파일로 수집하는 구조이므로, HOME 방문 기록에서 메뉴 재입력을 요구하지 않는다.

## 2. 범위

### 포함
- **DB & Alembic 마이그레이션 (`0003_store_tables_and_visits.py`):**
  - `store_tables`: `id`, `store_id`, `name`(예: `T1`, `창가 2인석`), `seats`(기본 2~4), `grid_x`(0~11), `grid_y`(0~7), `is_active`, `created_at`, `updated_at`
  - `visit_sessions`: `id`, `store_id`, `table_id`, `party_size`(1 이상), `age_band`(선택: `UNRECORDED`, `20S`, `30S`, `40S`, `50S_PLUS`, `MIXED`), `status`(`SEATED`, `PAID`, `LEFT`), `seated_at`, `paid_at`(nullable), `left_at`(nullable), `source`(`manual`), `notes`(nullable)
- **백엔드 API (`/api/v1/stores/{store_id}/...`):**
  - `POST /stores`: 매장 생성 시 `initial_table_count`(기본 6)와 `default_seats`(기본 4)를 받아 초기 테이블 `T1..Tn`을 그리드 좌표에 자동 배치 생성
  - `PATCH /stores/{store_id}`: 매장명, 영업일, 운영시간, 시간대 수정
  - `GET/POST /tables`, `PATCH /tables/{table_id}`: 테이블 추가, 좌석 수·이름·그리드 좌표(`grid_x`, `grid_y`)·활성 상태 수정 (현재 착석 세션 정보 `active_visit` 포함 반환)
  - `GET /visits`: 오늘 또는 기간별 방문 세션 목록 및 요약 집계(총 방문 팀 수, 총 방문 인원수, 현재 착석 중 테이블 수)
  - `POST /visits`: 테이블 착석/방문 기록 시작 (이미 해당 테이블에 활성 세션 `SEATED`/`PAID`가 있으면 409 차단)
  - `PATCH /visits/{visit_id}`: 인원/연령대 수정, `status="PAID"`(결제 완료 표시 — 테이블은 여전히 점유 상태 유지), `status="LEFT"`(실제 퇴점·테이블 비우기 — `left_at` 기록 및 과거 세션 보존)
- **프론트엔드 (`S00`, `S02`, `S07`):**
  - `S00` 매장 초기 설정 마법사(단계형: 1단계 매장명·영업일·운영시간 → 2단계 초기 테이블 수·기본 좌석 수 설정 후 자동 배치 생성, 뒤로 이동 시 입력값 유지)
  - `S02 HOME · 매장 배치도` (`HomePage.tsx`):
    - 상단 현황 카드: 현재 착석 테이블 수 / 오늘 누적 방문 인원(기록된 값 기준 명시) / POS·파일 연결 상태 / 빠른 이동
    - 기능형 그리드 테이블 배치도: 각 테이블의 이름·좌석 수·상태(`빈 테이블` / `착석중` / `결제완료·퇴점대기`)를 색상+아이콘/라벨로 표시
    - 테이블 클릭 시 우측/하단 빠른 조작 패널:
      - 빈 테이블 → `[착석 기록 시작]` (인원수 빠른 숫자 버튼 1~6+, 연령대 선택(기본 미기록))
      - 착석중 테이블 → `[인원/연령 수정]`, `[결제 완료 표시(퇴점 전)]`, `[퇴점 · 테이블 비우기]`
    - 하단 오늘의 방문 세션 이력 표(테이블 비우기 후에도 보존된 과거 기록 확인 가능)
  - `S07 환경설정 · 매장/테이블 관리` (`SettingsPage.tsx`): 매장 기본정보 수정, 테이블 추가/좌석 수/그리드 위치(행·열) 편집 및 비활성화

## 3. 수용 기준 (검증 가능)
- [x] AC-1 매장 생성 시 지정한 `initial_table_count`만큼 테이블이 자동 생성·배치된다.
- [x] AC-2 테이블 추가 및 좌석 수·이름·좌표(`grid_x`, `grid_y`) 수정이 정상 동작한다.
- [x] AC-3 빈 테이블에 방문 세션(`POST /visits`)을 시작하면 테이블의 `active_visit`이 조회되고, 이미 사용 중인 테이블에 중복 착석을 시도하면 409를 반환한다.
- [x] AC-4 방문 세션을 `PAID`(결제 완료)로 변경해도 세션은 종료되지 않고(`left_at` is null) 테이블 점유가 유지되며, `LEFT`(퇴점·테이블 비우기)로 변경해야 `left_at`이 기록되고 테이블이 비워진다(결제와 퇴점 분리).
- [x] AC-5 테이블 비우기(`LEFT`) 이후에도 `GET /visits`에 과거 방문 기록과 인원 합계가 보존된다.
- [x] AC-6 프론트엔드 `S00`, `S02`, `S07` 화면이 타입 검사·단위 테스트·프로덕션 빌드를 통과한다.
