# WO-20261111-003 — 분석·손익 화면 통합, 지출 관리 모달, 지급일 알림

| ID | 상태 | 작성일 | 관련 문서 | 관련 작업 | 관련 결정 |
|---|---|---|---|---|---|
| WO-20261111-003 | DRAFT | 2026-11-11 | 로드맵 1단계 | 선행: WO-20261111-002 | U-46 |

## 1. 목적 / 문제
지금은 입력칸과 대시보드가 한 화면에 섞여 복잡하다(사용자 의견 2026-11-11). 벤치마킹(캐시노트, 토스플레이스, Toast, Square, vanyanv/restaurant-dashboard)의 공통 패턴을 따른다. 첫 화면은 숫자 몇 개만 보여 주고, 누르면 상세가 열리며, 입력은 따로 받는다.

## 2. 범위
### 포함
1. **분석 화면 하나로 통합 (보기 전용).** 메뉴 `분석 대시보드`와 `손익`을 합친다. 화면에 입력칸을 두지 않는다.
   - 위쪽 카드: 매출, 지출, 남은 돈(영업이익). 각 카드에 지난달 대비 증감(▲▼)을 붙인다.
   - 지출 5묶음 막대. 묶음을 누르면 안에 든 항목이 펼쳐진다(보기만 한다).

     | 묶음 | 항목 |
     |---|---|
     | 재료비 | 식자재 사입비, 주류 사입비 |
     | 인건비 | 직원인건비, 4대보험비 |
     | 가게 유지비 | 임대료, 건물관리비, 전기세, 수도세, 가스비, 정수기, CCTV·캡스, 인터넷, 전화비, 포스기 |
     | 수수료·배달 | 카드수수료, 배민·요기요·쿠팡 수수료, 배달비, 포장비 |
     | 세금·기타 | 부가세, 세무기장료, 화재보험, 광고비, 사용자가 추가한 기타 항목 |

   - 최근 6개월 추이. 기존 판매 분석(메뉴별 매출 등)은 아래쪽에 그대로 둔다. 이 부분은 로드맵 3단계에서 다시 짠다.
   - 오른쪽 위 `지출 관리` 버튼을 누르면 모달이 열린다. 입력은 이 모달로만 한다.
2. **지출 관리 모달.**
   - 항목마다 종류를 정한다.

     | 종류 | 동작 |
     |---|---|
     | 고정 | 금액과 지급일(매월 n일)을 한 번 넣으면 매달 그 금액으로 기록된다. |
     | 변동 | 지급일을 정해 둔다. 금액은 그달에 확인하거나 수정하고, 없으면 지난달 금액으로 기록된다. |
     | 자동 | 총매출, 식자재 사입비(입고 합계), 카드수수료(매출 × 요율). 입력하지 않는다. 덮어쓰기는 지금처럼 가능하다. |
     | 수시 | 그달에 직접 추가한다(예: 주류 사입). |

   - 기본 종류: 임대료·건물관리비·정수기·CCTV·인터넷·전화비·포스기·세무기장료·화재보험은 고정, 전기·수도·가스·인건비·4대보험·광고비·부가세는 변동, 주류 사입비·배달앱 수수료·배달비·포장비는 수시. 사용자가 바꿀 수 있다.
   - **기타 항목은 행을 추가해 넣는다.** 이름, 종류, 금액, 지급일을 받는다. 지울 수도 있다.
   - 카드수수료율도 이 모달에서 설정한다.
   - 월을 고르면 그달 값을 고칠 수 있다(지난 달 정정).
3. **지급일 알림 (서비스 화면 안에만).**
   - 지급일 전날 매장 마감 시각이 지나면 알림을 만든다. 문구: `내일 전기세 700,000원 지출 예정`. 금액은 그달 값, 없으면 지난달 값이다.
   - 버튼은 `확인`과 `수정` 두 개다. `수정`을 누르면 지출 관리 모달이 열리고 그 항목으로 바로 이동한다.
   - 표시 위치: 상단 종 아이콘과 개수. 홈 위쪽에는 띠 배너로 띄운다.
   - 응답하지 않아도 지급일이 지나면 그 금액(그달 값, 없으면 지난달 값)으로 기록한다. "미확인" 같은 표시는 붙이지 않는다. 확인·수정 이력은 감사 로그에 남긴다.
   - 알림은 화면이 서버에 물어볼 때 만든다(별도 스케줄러 없음). 카카오톡과 폰 푸시는 제외한다(로그인 ⑦ 이후).
4. **DB.**
   - `expense_items`(store_id, 항목 코드 또는 이름, 종류, 기본 금액, 지급일, 정렬 순서, 활성 여부)를 추가한다. 매장 범위 RLS를 적용한다.
   - 기존 `monthly_expenses`에 `confirmed_at`을 추가한다.
   - 마이그레이션은 `0010`이다.
5. **테스트.**
   - 고정비가 매달 이어지는지
   - 변동비가 지난달 값으로 이어지는지
   - 알림 생성 시각(마감 전과 후, 월말, 지급일이 31일인 달)
   - 확인과 수정
   - 기타 행 추가와 삭제
   - 매장 격리

### 제외
- 카카오톡과 푸시 알림, 매장용 모바일 앱
- 근태와 연동한 인건비 자동 계산(로드맵 4단계)
- 판매 분석 재설계(로드맵 3단계)

## 3. 미결정 (PROVISIONAL로 진행, 사용자 확인 필요)
- 영업시간이 비어 있는 매장의 마감 시각: 기본 22:00으로 가정한다.
- 지급일이 그달에 없을 때(예: 31일을 2월에): 그달 말일로 본다.
- 예시 총매출 값: 엑셀은 38,000,000이고 영업이익률 17.6%와 맞는다. 사용자는 0이 하나 빠졌다고 했다. 380,000,000이면 영업이익률이 91.8%가 된다. 실제 값을 확인해야 한다.

## 4. 수용 기준
- AC-1 분석 화면에 입력칸이 없다. 모든 입력은 지출 관리 모달에서 한다.
- AC-2 고정비를 한 번 넣으면 다음 달 손익에 자동으로 잡힌다.
- AC-3 지급일 전날 마감 후 `내일 {항목} {금액}원 지출 예정` 알림이 뜬다. `수정`을 누르면 모달의 그 항목으로 간다.
- AC-4 응답하지 않아도 지급일 이후 손익에 그 금액이 기록된다.
- AC-5 기타 항목 행을 추가하고 삭제할 수 있다.
- AC-6 엑셀 예시 값으로 WO-20261111-002의 AC-1 숫자가 그대로 나온다.
- AC-7 CI가 초록불이고, 브라우저에서 확인한다(데스크톱과 모바일 폭).
