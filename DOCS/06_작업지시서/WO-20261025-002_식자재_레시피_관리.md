# WO-20261025-002 — 식자재 마스터 및 메뉴-식자재 공통 레시피 연결 (S04 + S03 연동)

| ID | 상태 | 작성일 | 관련 문서 | 관련 작업 | 관련 결정 |
|---|---|---|---|---|---|
| WO-20261025-002 | IN_PROGRESS | 2026-10-25 | [[음식점_AX_통합기획서_v1.0]] §4.1 #6·#7, [[음식점_AX_UI명세서_v0.1]] S03·S04 | 선행: [[WO-20261025-001_첫번째_vertical_slice]] | U-06, U-07, P-10, ADR-008, ADR-010 |

## 1. 목적 / 문제

사용자 2차 인터뷰 결정(`U-06`, `U-07`)에 따라 첫 번째 후속 작업으로 **A. 식자재 마스터 관리(`REQ-006`) 및 메뉴-식자재 레시피 연결(`REQ-007`, 화면 `S04` 및 `S03`)**을 구현한다. 또한 직전 리뷰([[REV-20261025-001_첫번째_vertical_slice]])의 경미한 발견 사항(`F-01`, `F-02`)을 함께 해결한다.
기획서 원칙(§1.6, §9.2)에 따라 **메뉴 화면(`S03`)에서 레시피를 편집하든 식자재·레시피 화면(`S04`)에서 편집하든 단일 공통 레시피 테이블(`recipes`, `recipe_items`)을 갱신**하도록 구현한다.

## 2. 범위

### 포함
- **DB & Alembic 마이그레이션 (`0002_ingredients_and_recipes.py`):**
  - `ingredients`: `id`, `store_id`, `name`, `base_unit`(`g`, `ml`, `ea`), `purchase_unit`(`kg`, `g`, `L`, `ml`, `ea`, `pack`), `conversion_factor`(`Numeric(12, 4)` — 1 구매단위당 기본단위 수량, 기본 1), `safety_stock`(`Numeric(12, 3)`, 선택), `notes`, `is_active`, `created_at`, `updated_at`
  - `recipes`: `id`, `store_id`, `menu_item_id`, `version`(정수, 기본 1), `status`(`COMPLETE`, `PARTIAL`), `effective_from`, `updated_at`
  - `recipe_items`: `id`, `recipe_id`, `ingredient_id`, `quantity`(`Numeric(12, 3)` — 1인분 기준 `base_unit` 사용량), `unit`(`base_unit` 스냅샷), `notes`
- **백엔드 API (`/api/v1/stores/{store_id}/...`):**
  - `GET/POST /ingredients`, `GET/PATCH /ingredients/{ingredient_id}` (활성 식자재명 중복 409, 비활성화 보존, 연결된 메뉴 수 `linked_menu_count` 포함 응답)
  - `GET /menus/{menu_id}/recipe` (메뉴별 현재 레시피 및 식자재 목록 조회)
  - `PUT /menus/{menu_id}/recipe` (메뉴의 1인분 레시피 항목 일괄 저장/갱신, 변경 시 `version` 증가 및 `audit_events` 기록, 빈 항목도 허용하여 `UNREGISTERED` / `PARTIAL` / `COMPLETE` 상태 자동 반영)
  - `GET /ingredients/{ingredient_id}/usages` (특정 식자재를 사용하는 메뉴·레시피 목록 조회)
  - 메뉴 목록(`GET /menus`)의 `recipe_status`를 실제 레시피 등록 여부에 따라 `"UNREGISTERED" | "PARTIAL" | "COMPLETE"` 및 `recipe_item_count`로 반환
- **프론트엔드 (`S04` & `S03`):**
  - `S04 식자재·레시피 관리` (`IngredientManagementPage.tsx`):
    - 식자재 마스터 목록(식자재명, 기본단위, 구매단위 및 변환비, 연결 메뉴 수, 상태, 관리)
    - 식자재 추가/수정 모달(양식당 예시 플레이스홀더: 파스타면, 올리브오일, 생크림, 베이컨 등, 단위 변환 자동 안내: 예 `1 kg = 1,000 g`)
    - 식자재별 연결 메뉴 조회 및 공통 레시피 편집 모달 호출
  - `S03 메뉴 관리` (`MenuManagementPage.tsx`):
    - 각 메뉴 행에서 실제 레시피 상태(`완성 (N종)` / `일부 미입력` / `미등록`) 표시 및 `[레시피 편집]` 버튼으로 공통 `RecipeEditorModal` 호출
    - `REV-001` `F-02` 수정: 검색/필터 중에도 전체 카테고리 드롭다운 목록이 유지되도록 별도 전체 메뉴 캐시 참조

### 제외 (비범위)
- 식자재 입고 거래·실재고 실사(`WO-20261025-005`에서 구현)
- 원가 시뮬레이션(`WO-20261025-006`에서 구현)

## 3. 수용 기준 (검증 가능)
- [x] AC-1 식자재를 생성·조회·수정·비활성화할 수 있으며, 활성 식자재명 중복 시 409를 반환한다.
- [x] AC-2 단위 변환 계수(`conversion_factor`)가 0 이하이면 422 검증 오류를 반환한다.
- [x] AC-3 메뉴에 레시피(식자재 + 1인분 사용량)를 저장하면 메뉴 조회 시 `recipe_status`가 `COMPLETE`(또는 `PARTIAL`)로 갱신되고, 식자재 조회 시 `linked_menu_count`가 정확히 집계된다.
- [x] AC-4 동일 메뉴에 같은 식자재를 중복 추가하려 하면 422 오류로 차단한다.
- [x] AC-5 레시피 수정 시 버전(`version`)과 `audit_events`가 기록된다.
- [x] AC-6 `REV-001 F-01`: 메뉴 `selling_price`를 기존 값에서 `null`로 PATCH 초기화하는 테스트가 통과한다.
- [x] AC-7 프론트엔드 `S04` 및 `S03` 공통 레시피 모달이 타입 검사·단위 테스트·빌드를 통과한다.
