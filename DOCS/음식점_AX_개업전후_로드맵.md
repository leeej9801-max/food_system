# 음식점 AX 도입 및 개발 로드맵

> **대상:** 개업까지 약 1~2개월 남은 개인 음식점 및 소규모 외식업 사업자  
> **범위:** 서빙·조리 로봇 제외. 데이터 기반 운영, 업무 자동화, AI 분석·예측 중심  
> **문서 목적:** 개업 전 데이터 구축부터 개업 후 운영 최적화까지 이어지는 AX 서비스의 사업 방향, 기능 범위, 개발 순서, 파일럿 검증 계획 정리

---

## 1. 핵심 제안

개업 예정 음식점은 과거 매출 데이터가 없기 때문에 오픈 초기부터 정교한 매출·수요 예측 AI를 제공하기 어렵다. 대신 개업 전부터 확보할 수 있는 메뉴, 레시피, 식자재 구매가격, 운영 계획 등을 구조화하고, 개업 이후에는 실제 매출·재고·폐기 데이터를 축적해 분석과 예측 기능을 단계적으로 확장하는 전략이 적절하다.

**권장 서비스 정의**

> 개업 전에는 음식점의 운영 데이터를 구조화하고, 개업 후에는 축적된 데이터를 활용해 운영 의사결정을 개선하는 AX 서비스.

### 초기 우선순위

1. 메뉴·레시피·식자재 데이터 구축
2. 메뉴별 식재료 원가 계산 및 가격 변동 시뮬레이션
3. 구매 내역 정리와 식자재·공급업체 관리
4. 개업 후 매출·재고·폐기 데이터 수집
5. 실제 데이터가 쌓인 뒤 판매량 예측 및 발주 권고 실험

처음부터 모든 업무를 자동화하기보다는, 파일 업로드와 간단한 입력으로 작동하는 MVP를 만들고 실제 사용 빈도와 효과가 확인된 기능부터 자동화한다.

---

## 2. 목표 고객과 고객 문제

### 2.1 목표 고객

- 1~2개월 이내에 개업할 예정인 개인 음식점 또는 소규모 외식업 사업자
- 예: 한식당, 분식점, 고깃집, 카페, 도시락·반찬 전문점
- 초기에는 한 업종 또는 메뉴·레시피 구조가 비교적 명확한 업종으로 범위를 좁히는 방안 권장

### 2.2 고객이 겪는 문제와 서비스 가치

| 고객이 처한 상황 | AX 서비스가 제공할 수 있는 가치 |
|---|---|
| 메뉴별 원가를 정확히 파악하기 어려움 | 레시피와 식자재 구매가격을 연결해 메뉴별 식재료 원가 계산 |
| 초기 식자재를 얼마나 구매해야 할지 불확실함 | 운영 가정을 바탕으로 구매량 시나리오를 계산하고 발주 목록 생성 |
| 식자재 구매가격이 자주 바뀜 | 구매 내역을 누적해 가격 변동과 메뉴 원가 영향 분석 |
| POS와 재고관리를 별도로 수행함 | 매출·레시피·식자재 소비량을 연결할 수 있는 데이터 구조 구축 |
| 직원 교육·마감 절차가 정리되지 않음 | 매장 운영 매뉴얼 정리 및 내부 검색 도우미 제공 |
| 개업 후 운영 상황을 파악하기 어려움 | 실제 매출·원가·폐기 데이터를 기반으로 운영 현황 분석 |

**주의:** 모든 기능에 AI가 필요한 것은 아니다. 원가·재고 계산은 검증 가능한 수식과 코드로 처리하고, AI는 문서에서 데이터 추출, 품목 후보 매칭, 자연어 질의, 분석 결과 설명, 개선안 초안 생성 등에 활용하는 것이 적절하다.

---

## 3. 서비스 구조: 개업 전 준비부터 개업 후 최적화까지

서비스는 세 단계로 발전시킨다.

| 제품 단계 | 핵심 서비스 | AI 활용 | 기대하는 가치 |
|---|---|---|---|
| Phase 1. 개업 준비 | 메뉴·레시피·원가·구매 관리 | 거래명세서 정보 추출, 품목 매칭, 분석 보고서 | 오픈 전에 필요한 데이터와 운영 기준 정리 |
| Phase 2. 초기 운영 | 매출·재고·폐기 분석 | 자연어 분석, 원인 탐색 보조 | 운영 현황 파악과 반복 업무 절감 |
| Phase 3. 운영 최적화 | 판매량 예측·발주 권고 | 시계열 예측, 예측 결과 설명 | 식자재 구매 및 준비량 의사결정 개선 |

개업 전 고객에게도 가치를 제공하려면 오픈 이후의 매출 데이터가 없어도 작동하는 기능이 필요하다. 따라서 Phase 1을 MVP의 중심에 둔다.

## 4. 개업 전후 전체 로드맵

개업까지 8주가 남았다고 가정한 예시 로드맵이다. 실제 남은 기간에 따라 단계를 압축하되, 필수 데이터 검증을 생략하지 않는다.

| 단계 | 시점 | 핵심 목표 | 주요 결과물 |
|---|---|---|---|
| 1 | 오픈 8~7주 전 | 매장 현황 및 업무 분석 | 고객 진단표, 도입 범위 |
| 2 | 오픈 7~5주 전 | 메뉴 및 원가 데이터 구축 | 메뉴 마스터, 레시피, 원가표 |
| 3 | 오픈 5~3주 전 | 구매·재고 관리 체계 구축 | 식자재 목록, 구매 기준, 초기 재고 계획 |
| 4 | 오픈 3~1주 전 | 시스템 연결 및 운영 시뮬레이션 | 데이터 연동, 운영 매뉴얼, 테스트 결과 |
| 5 | 오픈 직전~7일 | 실제 운영 데이터 수집 시작 | 매출·구매·재고·폐기 데이터 |
| 6 | 오픈 2~4주 후 | 운영 현황 분석 | 초기 운영 리포트, 개선 과제 |
| 7 | 오픈 5~8주 후 | 데이터 기반 운영 개선 | 판매량 예측 실험, 구매량 개선안 |
| 8 | 오픈 9~12주 후 | 검증된 기능 중심으로 확대 | 검증된 예측·분석 기능, 자동화 확대 |

**단계 전환 원칙:** 일정이 지났다는 이유만으로 다음 기능을 자동 도입하지 않는다. 데이터의 양과 품질, 사용자 활용도, 예측 성능 및 업무 개선 효과를 확인한 뒤 확장한다.

## 5. 단계별 실행 계획

### 5.1 오픈 8~7주 전: 매장 진단

이 단계에서는 매장의 운영 형태와 필요한 AX 기능을 파악한다. 모든 음식점에 동일한 기능을 제공하기보다 메뉴 구성과 조리·판매 방식에 맞게 범위를 설정한다.

#### 확보할 데이터

| 데이터 분류 | 확보할 정보 | 활용 목적 |
|---|---|---|
| 매장 기본정보 | 업종, 영업시간, 좌석 수, 운영 형태 | 서비스 설정 |
| 메뉴 정보 | 메뉴명, 판매가격, 판매 방식 | 메뉴 분석의 기준 |
| 레시피 정보 | 재료, 사용량, 조리 수율 | 메뉴별 원가 계산 |
| 식자재 구매정보 | 품목, 단위, 구매가격, 공급업체 | 구매 관리 |
| 운영 계획 | 영업일, 예상 주문 처리량, 인력 계획 | 초기 운영 시나리오 수립 |
| 시스템 정보 | POS, 배달 플랫폼, 회계·재고관리 도구 | 데이터 연동 방식 결정 |

POS 도입 여부와 외부 데이터 접근 가능성도 확인한다. POS마다 외부 API, 내보내기 기능, 사용 권한이 다르므로 모든 시스템의 실시간 연동을 초기 전제로 삼지 않는다.

#### 산출물

- 고객 진단표
- 현재 업무 흐름도
- 사용할 데이터 목록과 확보 방법
- MVP 범위 및 연동 우선순위
- 고객별 초기 데이터 구축 계획

### 5.2 오픈 7~5주 전: 메뉴 및 식자재 데이터 구축

오픈 전에는 과거 매출이 없더라도 메뉴·레시피·구매가격은 확보할 수 있다. 이 데이터를 이용해 개업 전에 쓸 수 있는 핵심 기능을 개발한다.

#### 기능 A: 메뉴별 원가 계산

가상의 제육볶음 1인분 레시피 예시:

| 식자재 | 사용량 | 단위 구매가격 | 해당 메뉴 원가 |
|---|---:|---:|---:|
| 돼지고기 | 180g | 10,000원/kg | 1,800원 |
| 양파 | 50g | 2,000원/kg | 100원 |
| 양배추 | 70g | 2,000원/kg | 140원 |
| 양념장 | 40g | 5,000원/kg | 200원 |
| **합계** | | | **2,240원** |

위 숫자는 설명을 위한 가상 예시다. 메뉴 판매가격이 12,000원이라면 식재료비 비율은 약 18.7%다.

`식재료비 비율 = 메뉴 1인분 식재료 원가 ÷ 메뉴 판매가격 × 100`

이 비율에는 인건비, 임차료, 공과금, 포장비 등 다른 비용이 포함되지 않는다. 식재료비 비율만으로 전체 수익성을 판단하지 않도록 메뉴별 공헌이익과 기타 비용을 구분한다.

#### 기능 B: 구매 내역 정리

거래명세서·구매 내역에서 다음 정보를 추출한다.

- 식자재명
- 구매 수량 및 단위
- 단위당 가격
- 공급업체
- 구매일

AI가 유사한 품목명을 같은 품목일 가능성이 있는 후보로 묶되, 잘못된 품목 통합을 방지하기 위해 사용자 확인 절차를 제공한다.

#### 기능 C: 메뉴별 원가 변화 시뮬레이션

- 특정 식자재 가격이 5%, 10%, 20% 상승했을 때 메뉴별 원가 영향 계산
- 판매가격을 유지할 때 공헌이익 변화 표시
- 가격 조정 또는 레시피 변경 시나리오 비교

이 기능은 과거 판매 데이터를 요구하지 않는다. 계산은 코드로 처리하고, AI는 영향과 대안을 설명하는 역할을 맡는다.

#### 산출물

- 메뉴 마스터
- 레시피·수율 입력표
- 식자재 마스터 및 단위 표준화 규칙
- 메뉴별 원가표
- 구매 내역 업로드 및 검수 기능
- 가격 변동 시뮬레이션

### 5.3 오픈 5~3주 전: 초기 구매·재고 관리

실제 판매량이 없으므로 AI가 정확한 발주량을 예측한다고 표현하지 않는다. 사업자가 설정한 운영 가정을 이용해 시나리오를 계산한다.

#### 필요한 정보

- 영업일과 영업시간
- 메뉴별 예상 판매량 범위
- 메뉴별 레시피
- 현재 재고량
- 공급업체 납품 주기
- 최소 주문량
- 식자재별 보관 기간 및 유통기한

예상 판매량은 낮음·기준·높음의 시나리오로 나눌 수 있다. 이 값은 AI가 학습해 도출한 예측이 아니라 사업자가 설정한 가정임을 화면에서 명확히 표시한다.

#### 초기 기능

- 식자재별 재고 등록
- 공급업체 및 구매가격 관리
- 메뉴별 예상 식자재 사용량 계산
- 구매 목록 자동 생성
- 초기 재고 구매 시나리오 비교
- 유통기한 및 발주 관련 알림

초기 단계에서는 완전자동 발주보다 구매 목록 생성과 사장님 승인 절차를 우선한다.

### 5.4 오픈 3~1주 전: 운영 시뮬레이션 및 직원 교육

#### 검증 항목

1. **데이터 연동 테스트:** POS 내보내기 파일에서 메뉴명, 판매량, 판매가격이 정상적으로 연결되는지 확인한다.
2. **원가 계산 테스트:** 시스템 결과와 독립적으로 계산한 Excel 결과가 일치하는지 확인한다.
3. **운영 시뮬레이션:** 가상 매출·구매 데이터를 넣어 재고 차감, 원가 계산, 보고서 생성이 정상 작동하는지 확인한다.
4. **직원 교육:** 매출 확인, 재고 입력, 구매 내역 등록, 폐기량 기록 등 실제 업무를 교육한다.
5. **오류 처리:** 누락된 메뉴, 알 수 없는 품목명, 단위 불일치, 잘못된 가격 등 예외 상황을 테스트한다.

가상 데이터는 시스템 테스트 목적으로만 사용한다. 가상 데이터로 만든 결과를 실제 매장의 매출 전망인 것처럼 표시하지 않는다.

#### 산출물

- 시스템 테스트 결과
- 직원용 간단 매뉴얼
- 매장별 메뉴·레시피·식자재 데이터
- 매출·구매·재고 기록 절차
- 오류 및 문의 처리 절차

## 6. 오픈 후 데이터 수집 설계

오픈 이후에는 계획과 가정 대신 실제 운영 결과를 기록한다.

| 데이터 | 수집 방식 | 권장 주기 | 활용 목적 |
|---|---|---|---|
| 메뉴별 판매량 | POS 연동 또는 파일 업로드 | 매일 | 수요 분석 |
| 식자재 구매 내역 | 파일 업로드 또는 문서 추출 | 구매 시 | 원가·가격 변동 분석 |
| 현재 재고 | 재고 시스템 또는 간편 입력 | 입출고 시·마감 시 | 발주량 계산 |
| 식자재 폐기량 | 직원 입력 | 마감 시 | 폐기 비용 분석 |
| 품절 기록 | 직원 입력 또는 품절 상태 기록 | 발생 시 | 미충족 수요 파악 |
| 영업시간 및 운영 일정 | 일정 기록 | 일별 | 시간대별 수요 분석 |
| 고객 리뷰 | 허용된 수집 방식 또는 사용자 제공 자료 | 주기적 | 고객 불만 분석 |

매출 데이터만으로 실제 식자재 소비량을 정확히 알기는 어렵다. 레시피상 이론 소비량과 실제 소비량 사이에는 조리 손실, 직원 식사, 폐기, 레시피 편차 등의 차이가 생길 수 있다. 따라서 재고와 폐기량도 함께 기록해야 분석의 신뢰도를 높일 수 있다.

처음부터 모든 항목을 완벽하게 기록하기보다 직원이 무리 없이 지속할 수 있는 최소한의 데이터부터 시작한다.

## 7. 오픈 후 30·60·90일 기능 발전 계획

### 7.1 오픈 후 1~30일: 실제 운영 현황 분석

**목표:** 예측 모델을 고도화하기보다 데이터가 안정적으로 수집되고 계산 결과를 신뢰할 수 있도록 한다.

#### 기능

- 일별 매출 및 메뉴별 판매량 요약
- 레시피와 구매가격을 연결한 메뉴별 식재료 원가 계산
- 구매가격 변동 및 원가가 증가한 메뉴 확인
- 이론상 재고와 실제 재고 비교
- 폐기량 및 품절 기록 축적
- 자연어 기반 운영 데이터 질의(데이터가 준비된 범위 내)

#### KPI 예시

- 메뉴와 레시피 연결률
- 구매 내역 등록률
- 데이터 입력에 걸리는 시간
- 메뉴별 원가 계산 가능 비율
- 재고 기록의 완전성

초기 목표치는 고객 규모와 실제 운영 방식에 맞춰 정한다.

### 7.2 오픈 후 31~60일: 운영 패턴 분석과 예측 실험

한두 달의 데이터로 요일별 판매량과 메뉴별 수요 패턴을 탐색할 수 있지만, 개업 효과·홍보 이벤트·초기 고객 유입 등이 판매량에 영향을 줄 수 있다. 초기 패턴을 장기적인 수요로 일반화하지 않는다.

#### 기능

- 평일·주말·시간대별 메뉴 판매량 분석
- 구매가격 변동 시뮬레이션
- 단순한 기준 모델을 활용한 초기 수요예측 실험
- 예측 결과와 실제 판매량 비교
- 재고·납품 주기·최소 주문량을 반영한 구매 권고

예측 모델은 최근 평균 또는 전주 같은 요일의 판매량 등 단순 기준 모델과 비교한다. 복잡한 모델이 더 나은 성능을 지속적으로 보일 때만 도입을 확대한다.

60일 데이터는 초기 패턴 탐색에는 도움이 될 수 있지만, 연간 계절성이나 장기 수요 변화를 안정적으로 학습하기에는 부족할 수 있다.

### 7.3 오픈 후 61~90일: 검증된 기능 중심으로 자동화

#### 기능

- 단순 기준 모델보다 예측 성능이 확인된 메뉴에 대해 조리 준비량 권고
- 재고 데이터가 신뢰할 수 있는 경우 발주 권고 자동 생성
- 리뷰 분석을 반복 문제 및 개선 과제 관리로 확장
- 매장별 주간 운영 리포트 자동 생성
- 실제 사용 빈도가 높은 반복 업무 자동화

실제 발주는 초기에는 사장님 승인 후 진행한다. 예측이 부정확하거나 재고 데이터가 불완전하다면 자동화 범위를 확대하지 않는다.

**90일 목표:** 모든 업무를 AI로 대체하는 것이 아니라, 실제 데이터로 효과가 확인된 기능을 반복적인 의사결정에 정착시키는 것.

## 8. MVP 기능 범위

### 8.1 MVP에 포함할 기능

1. 매장·메뉴 기본정보 등록
2. 레시피 및 식자재 사용량 입력
3. 식자재 마스터와 단위 표준화
4. 구매 내역 CSV·Excel 업로드
5. 메뉴별 식재료 원가 계산
6. 구매가격 변동에 따른 원가 시뮬레이션
7. 초기 재고·구매 목록 생성
8. 기본 운영 리포트
9. AI 기반 문서 정보 추출과 품목 매칭 보조
10. 사용자 확인·승인 및 오류 수정 기록

### 8.2 초기 MVP에서 제외할 기능

- 모든 POS와 실시간 연동
- 완전자동 식자재 발주
- 데이터가 거의 없는 상태에서의 고정밀 매출 예측
- 카메라 기반 음식물 인식
- 모든 배달·예약 플랫폼 통합
- 복잡한 AI 에이전트의 자동 업무 실행

초기에는 파일 업로드와 간단한 입력만으로 작동하도록 하고, 실제 고객 수요와 데이터 연동 가능성이 확인된 POS부터 연동한다.

## 9. 서비스 아키텍처 구상

초기 구현은 가능한 한 단순하게 구성한다.

### 데이터 흐름

`POS·구매 파일·수기 입력 → 데이터 표준화 및 검수 → 메뉴·레시피·식자재 데이터베이스 → 계산·분석 로직 → AI 설명·보고서 → 사용자 확인·수정`

### 주요 데이터 엔터티

- **Store:** 매장 정보
- **Menu:** 메뉴명, 판매가격, 판매 상태
- **Ingredient:** 식자재명, 기본 단위, 보관 정보
- **Recipe:** 메뉴별 식자재와 사용량, 수율
- **Supplier:** 공급업체 정보
- **Purchase:** 구매 일자, 품목, 수량, 단가, 공급업체
- **Inventory:** 재고 입출고 및 실사 기록
- **Sales:** 날짜·시간, 메뉴, 수량, 판매가격, 할인
- **Waste:** 폐기 품목, 수량, 사유, 기록 시각
- **Stockout:** 품절 메뉴와 시간대
- **Recommendation:** AI·규칙 기반 분석 결과, 근거, 사용자 승인 상태

### 설계 원칙

- 계산값은 검증 가능한 수식 또는 코드로 산출한다.
- AI가 원가·재고·발주 수량을 근거 없이 생성하지 않도록 한다.
- AI가 만든 품목 매칭 결과에는 확인 상태를 기록한다.
- 분석 결과마다 사용한 데이터 기간과 근거를 표시한다.
- 사용자가 AI 제안을 수락·수정·거절했는지 기록한다.
- 가상 데이터와 실제 운영 데이터를 명확히 구분한다.
- 개인정보 및 결제정보는 불필요하게 수집하지 않는다.

## 10. 파일럿 검증 계획

처음부터 전국 음식점을 대상으로 하기보다, 한 업종을 중심으로 소수 매장에서 파일럿을 진행한다. 초기 인터뷰 3~5곳, 파일럿 1~3곳은 시장 규모를 추정하는 표본이 아니라 요구사항과 구축 과정을 검증하기 위한 제안이다.

### 검증 지표

| 검증 영역 | 지표 | 확인할 내용 |
|---|---|---|
| 고객 확보 | 상담 대비 파일럿 전환율 | 개업 전부터 도입할 의향이 있는가? |
| 초기 구축 | 매장당 데이터 구축 시간 | 맞춤 설정에 지나치게 많은 시간이 드는가? |
| 업무 효율 | 원가·운영 보고서 작성 시간 | 실제 관리 업무가 줄어드는가? |
| 데이터 품질 | 메뉴·레시피 연결률 | 계산에 필요한 데이터가 충분한가? |
| 비용 관리 | 구매가격·폐기량 분석 활용률 | 실제 구매·조리 계획에 활용하는가? |
| 예측 성능 | 단순 기준 모델 대비 예측 오차 | AI 예측이 단순한 방식보다 나은가? |
| 고객 유지 | 월간 사용률 및 재사용 의향 | 오픈 준비 이후에도 사용할 이유가 있는가? |

핵심 KPI는 AI 사용 횟수가 아니다. 원가를 파악하는 시간이 줄었는지, 구매가격 변화를 놓치지 않게 됐는지, 폐기량을 기록하고 관리하게 됐는지 등 실제 업무가 바뀌었는지를 측정한다.

### 권장 파일럿 진행 방식

1. 고객 인터뷰와 현재 업무 흐름 파악
2. POS·구매 내역 샘플 확보 및 데이터 진단
3. 메뉴·레시피·식자재를 연결하는 데이터 구축
4. 실제 매장에서 MVP 사용
5. 사용률, 데이터 품질, 업무 시간 변화 기록
6. 고객 피드백에 따라 기능 우선순위 조정
7. 효과가 확인된 기능만 다음 단계로 확대

## 13. 권장 실행 순서: 지금부터 무엇을 할 것인가

### 1단계: 고객 인터뷰와 데이터 진단

개업 예정 음식점 3~5곳을 만나 다음을 확인한다.

- 업종과 메뉴 수
- 레시피 관리 방식
- 식자재 구매 및 가격 확인 방식
- POS 선정 여부와 데이터 내보내기 가능성
- 재고·폐기 관리 방식
- 개업 준비 중 가장 번거로운 관리 업무
- 오픈 후에도 계속 사용하고 싶은 기능

### 2단계: 개업 전 MVP 개발

- 메뉴·레시피 입력
- 식자재 마스터 및 단위 표준화
- 구매 내역 CSV·Excel 업로드
- 메뉴별 식재료 원가 계산
- 구매가격 변동 시뮬레이션
- 초기 재고·구매 목록 생성
- 기본 보고서 및 AI 설명

### 3단계: 1~3개 매장에서 파일럿

초기 데이터 구축에 걸리는 시간, 고객의 사용 빈도, 계산 결과의 정확성, 실제 업무 시간 변화 등을 확인한다.

### 4단계: 오픈 당일부터 데이터 누적

가능한 경우 POS 연동을 사용하고, 그렇지 않다면 파일 업로드와 간단한 입력부터 시작한다. 메뉴 판매량, 구매 내역, 실제 재고, 폐기량, 품절 기록을 수집한다.

### 5단계: 데이터가 쌓인 뒤 예측 기능 실험

단순한 기준 모델과 AI 모델을 비교해 실제 개선이 확인된 경우에만 수요예측 및 발주 권고를 본격 도입한다.

---

## 14. 결론

개업 예정 음식점을 대상으로 한 AX 서비스는 처음부터 고정밀 매출 예측 AI를 제공하는 방식보다, **개업 전 원가·구매 데이터 체계를 구축하고 개업 후 실제 데이터를 활용해 운영을 개선하는 방식**으로 시작하는 것이 타당하다.

초기 MVP의 핵심은 메뉴·레시피·식자재 구매가격을 연결하는 것이다. 이 구조가 마련되면 구매 내역 정리, 원가 변동 분석, 초기 재고 계획, 운영 보고서 등의 기능을 제공할 수 있다. 오픈 이후 매출·재고·폐기 데이터가 누적되면 수요예측과 발주 권고를 실험할 수 있다.

사업적으로는 한 업종에서 소수 매장으로 파일럿을 진행하고, 설정에 드는 시간과 실제 업무 개선 효과를 검증해야 한다. AI 기능의 개수보다 데이터 품질, 사용성, 계산의 신뢰성, 실제 업무 프로세스의 변화가 서비스의 핵심 성과가 되어야 한다.

### 가장 가까운 다음 단계

**개업 예정 음식점 3~5곳의 요구사항을 인터뷰하고, POS 매출 샘플과 식자재 구매내역 샘플을 확보한 뒤, 메뉴·레시피·식자재를 연결하는 최소 데이터 구조부터 설계한다.**
