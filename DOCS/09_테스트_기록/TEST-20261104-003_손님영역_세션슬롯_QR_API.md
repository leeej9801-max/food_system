## 손님 API 테스트 항목 (SQLite, `tests/api/test_guest_api.py`)
- 첫 스캔: 기기 쿠키(HttpOnly) 발급, 응답에 매장 ID·기기 토큰·개인정보 없음, DB에는 토큰 해시만 저장
- 모르는 토큰·회전 전 토큰 404, 꺼진 테이블 토큰 404 (구분해서 알려주지 않음)
- 첫 스캐너가 인원수로 열고 두 번째 기기는 인원 재입력 없이 합류, 다른 인원수는 덮어쓰지 않고 `party_size_mismatch`
- 인원수 없이 열기 422 `PARTY_SIZE_REQUIRED`, 손님 세션이 열린 테이블에 직원 착석 409
- 케이스 A: 직원이 먼저 연 세션에 손님이 같은 인원으로 합류하면 `party_size_source=GUEST_QR`
- 케이스 H: `new_party=true`면 이전 세션을 `LEFT`/`NEXT_PARTY`로 닫고 새로 연다
- 슬롯: `+` 추가와 좌석 초과 표시, 빈 실루엣만 제거, 가져간 슬롯 제거 409, 마지막 1자리 제거 409, 20자리 초과 409 `SLOT_LIMIT`
- 가져가기 충돌 409, 표시 거부는 내 슬롯만(남의 슬롯 403)
- 열린 세션 없이 슬롯 동작 409 `NO_OPEN_SESSION`
- 직원 인원수 변경 시 슬롯 동기화, 직원 퇴점 시 `closed_reason=CLEARED`, 열린 세션 중복 착석 409

## PostgreSQL 격리 테스트 신규 항목 (`tests/isolation/test_api_rls.py`)
- 런타임 계정(RLS 적용) 아래에서 QR 조회·열기·가져가기 동작, 매장 A 세션이 매장 B 방문 목록과 B 토큰 화면에 안 보임
- 직원이 내 매장 경로로 다른 매장 테이블의 QR 조회·회전 시 404, 다른 매장 토큰은 그대로 유효
- 범위 없는 런타임 계정: `table_qr_tokens`·`session_slots` 0행, `app_resolve_table_qr`는 맞는 토큰 1개만 풀고 빈 토큰은 0행
- 매장 A 범위에서 매장 B `store_id`로 슬롯 INSERT 시 RLS 위반으로 거부
